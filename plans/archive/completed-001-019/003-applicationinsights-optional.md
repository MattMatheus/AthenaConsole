## Why this matters

`applicationinsights` is declared as a hard runtime `dependency` in both
`packages/core` and `apps/api`, but the integration is **off by default** and the
loader is fully resilient to the package being absent. This single dependency
pulls in the entire vulnerable transitive chain flagged by `npm audit`: a
**CRITICAL** `protobufjs` advisory plus **HIGH** advisories in `@grpc/grpc-js` and
the OpenTelemetry Prometheus exporter — shipped to every install for a feature
most operators never enable. Because the loader uses a lazy `createRequire` and
already returns `undefined` when the module is missing, the package can be made an
explicit opt-in install, removing the chain from the default install graph with no
runtime behavior change when telemetry is left disabled.

## Current state

- `packages/core/package.json` → `dependencies` includes `"applicationinsights": "^3.12.0"`.
- `apps/api/package.json` → `dependencies` includes `"applicationinsights": "^3.12.0"`, but `apps/api/src/main.ts` imports only `{ createApiServer, loadConfig } from "@athena/core"` — it never imports `applicationinsights` directly. It is a **dead dependency** in `apps/api`.
- The loader, `packages/core/src/observability/application-insights.ts`, is absence-resilient:
  - It defines its own structural types (`TelemetryClientLike`, `AppInsightsSetupChain`) — there is **no static `import ... from "applicationinsights"`** anywhere.
  - `initializeApplicationInsights` early-returns when telemetry is disabled:
    ```ts
    // application-insights.ts:48
    const appInsights = config.telemetry?.appInsights;
    if (!appInsights?.enabled || !appInsights.connectionString) {
      return;
    }
    ```
  - The actual module load goes through `requireApplicationInsights()`, which is wrapped in `try { ... } catch { return undefined; }` (around lines 78 and 157) — a missing module degrades telemetry silently, it does not crash.
- **Why not just `optionalDependencies`?** npm installs `optionalDependencies` by default (they are only skipped with `--omit=optional` or on build failure). That would NOT remove the vulnerable chain from a normal `npm install`. To actually drop it from the default graph, the package must be removed from the install manifests and documented as an explicit opt-in install.

## Steps

### Step 1: Confirm no static import or test hard-dependency

```
grep -rn "from \"applicationinsights\"\|require(\"applicationinsights\")\|import(\"applicationinsights\")" packages apps --include='*.ts'
grep -rln "applicationinsights\|appInsights\|AppInsights" packages/core/tests
```

- The first grep should return **nothing** (the loader uses a variable `require` from `createRequire`, not a literal string the grep matches — confirm there is no literal static import).
- If a test asserts that telemetry actually initializes the real `applicationinsights` module (not just config parsing), STOP and report it — removing the package would break that test and needs a decision.

**Verify**: no static imports found; no test requires the real module.

### Step 2: Remove from `apps/api`

Delete the `"applicationinsights": "^3.12.0"` line from `apps/api/package.json` `dependencies`. (It is unused there.)

### Step 3: Remove from `packages/core`

Delete the `"applicationinsights": "^3.12.0"` line from `packages/core/package.json` `dependencies`.

Then from the repo root run `npm install` to regenerate the lockfile without the chain.

**Verify**:
- `npm run typecheck` → exit 0 (proves nothing compiles against the now-absent package; expected, since the loader has no static import).
- `npm --workspace @athena/core run test:unit` → all pass.

### Step 4: Document the opt-in

Telemetry now requires operators to install the package explicitly. Add a short note where deployment/telemetry config is documented — `server.env.example` (near any App Insights / telemetry env var) and/or `docs/developer/product-dev-guides/local-server-deployment.md`:

> Application Insights telemetry is optional and not installed by default. To enable
> it, set the telemetry connection string env var **and** install the SDK in the
> deployment: `npm install applicationinsights`. If the package is not installed,
> telemetry is silently disabled and the app runs normally.

**Verify**: `npm run check:docs` → exit 0 (if you added a markdown link; otherwise this is a no-op).

### Step 5: Confirm the security win

```
npm audit --omit=dev
```

**Verify**: the `protobufjs` (critical) and `@grpc/grpc-js` / OpenTelemetry exporter (high) advisories that traced through `applicationinsights` are gone from the production dependency audit (or reduced to advisories from a different, still-present package — note any remainder in your report).
