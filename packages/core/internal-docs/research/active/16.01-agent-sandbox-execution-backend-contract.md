# Agent Sandbox Execution Backend Contract (First Pass)

## Date

2026-02-18

## Executive Summary

First-pass recommendation: integrate Agent Sandbox as an optional Team Orchestrator execution backend via a narrow control-plane interface that maps `runId` to sandbox identity and keeps Kubernetes/CRD details out of API route handlers.

Inference from sources:
- Agent Sandbox already provides lifecycle-oriented CRDs (`Sandbox`, `SandboxTemplate`, `SandboxClaim`, plus `SandboxWarmPool` extension), which aligns with Team Orchestrator run lifecycle management.
- Warm-pool behavior can materially reduce startup latency for isolated runs (GKE docs describe creation "under a second" for pre-warmed sandboxes).

## Lifecycle Mapping

1. `run accepted`:
- Team Orchestrator allocates run state and requests a sandbox claim from a template.

2. `run started`:
- Team Orchestrator waits for sandbox readiness, then dispatches provider/tool execution through the sandbox endpoint.

3. `run cancelled/timeout`:
- Team Orchestrator requests termination on sandbox identity and marks run cancellation outcome.

4. `run completed/failed`:
- Team Orchestrator persists final status and triggers cleanup or retention policy for sandbox resources.

## Proposed Backend Interface (Control-Plane Boundary)

```ts
export interface SandboxExecutionBackend {
  claim(request: {
    runId: string;
    sessionId: string;
    templateRef: string;
    warmPoolRef?: string;
    labels: Record<string, string>;
    annotations: Record<string, string>;
    timeoutMs?: number;
  }): Promise<{
    sandboxId: string;
    claimName: string;
    namespace: string;
    runtimeClassName?: string;
    claimedAt: string;
  }>;

  waitReady(request: {
    runId: string;
    sandboxId: string;
    timeoutMs: number;
  }): Promise<{
    ready: boolean;
    observedAt: string;
    endpoint?: string;
    reason?: string;
  }>;

  terminate(request: {
    runId: string;
    sandboxId: string;
    reason: "cancelled" | "timeout" | "failed" | "cleanup";
  }): Promise<{ terminated: boolean; observedAt: string }>;

  cleanup(request: {
    runId: string;
    sandboxId: string;
    ttlSeconds?: number;
  }): Promise<{ cleaned: boolean; observedAt: string }>;
}
```

## State and Telemetry Additions

Persisted correlation (minimum):
- `runId`
- `sessionId`
- `sandboxId`
- `sandboxClaimName`
- `sandboxNamespace`
- `runtimeClassName`
- `sandboxTemplateRef`
- `sandboxWarmPoolRef` (optional)
- `claimedAt`, `readyAt`, `terminatedAt`, `cleanedAt`

Event payload additions (bounded):
- `sandbox.phase`: `claiming|ready|running|terminating|terminated|cleanup-pending|cleanup-failed`
- `sandbox.backend`: `agent-sandbox`
- `sandbox.latencyMs.claimToReady`
- `sandbox.warmPoolHit` (inferred true/false from claim metadata)

## Failure Taxonomy (First Pass)

Retryable:
- claim conflict/contention
- transient Kubernetes API failure
- warm-pool empty fallback requiring cold sandbox

Terminal:
- template not found
- policy/admission denial
- runtimeClass unsupported on target cluster

Operator-action-required:
- repeated cleanup failure with leaked sandboxes
- run cancellation race where sandbox is already gone but Team Orchestrator run remains active

## Capability Gating and Fallback

- Add backend capability flag: `executionBackend.sandbox.enabled`.
- If disabled/unavailable, Team Orchestrator stays on current provider execution path.
- If enabled but claim fails terminally, fail run with structured backend error; do not silently bypass sandbox in high-security policy contexts.

## Risks and Mitigations

1. Identity drift (`runId` vs sandbox resource):
- Mitigation: persist claim correlation immediately after successful claim response.

2. Cancellation races:
- Mitigation: idempotent `terminate()` semantics; treat "already terminated" as successful stop.

3. Orphaned resources:
- Mitigation: explicit cleanup step with retry/backoff and periodic scavenger based on run terminal age.

## Proposed Team Orchestrator Touchpoints

- `src/control-plane/interfaces.ts`: backend contract interface.
- `src/control-plane/backends.ts`: backend adapter wiring.
- `src/control-plane/services.ts`: orchestration and event emission.
- `src/shared/contracts.ts`: optional telemetry/event DTO extensions.
