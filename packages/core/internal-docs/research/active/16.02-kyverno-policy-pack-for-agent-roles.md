# Kyverno Policy Pack for Agent Roles (First Pass)

## Date

2026-02-18

## Executive Summary

First-pass recommendation: ship a minimal policy pack with:
- `validate`: block unsafe pod specs by role
- `mutate`: stamp required metadata and inject deterministic env config
- `generate`: create per-session network controls

Inference from sources:
- Kyverno supports validate/mutate/generate as first-class policy types and can be used to enforce non-bypassable cluster-side controls.

## Team Orchestrator Metadata Contract (Required for Deterministic Targeting)

Team Orchestrator should stamp these labels/annotations on all agent workloads:

- labels:
  - `athena.dev/agent-role`: `lore-audit|build-agent`
  - `athena.dev/run-id`: stable `runId`
  - `athena.dev/session-id`: stable `sessionId`
  - `athena.dev/control-plane`: `v1`
- annotations:
  - `athena.dev/policy-profile`: profile identifier (`strict-audit`, `restricted-build`)
  - `athena.dev/cleanup-ttl-seconds`: lifecycle hint

## Role Intents

`lore-audit`:
- deny external egress
- require read-only root filesystem
- require non-root execution
- allow only approved images

`build-agent`:
- allow restricted egress destinations
- require non-root + dropped capabilities baseline
- inject short-lived token reference metadata (not raw secret content)

## Validate Policy Example (Role: lore-audit)

```yaml
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: athena-lore-audit-validate
spec:
  validationFailureAction: Enforce
  background: false
  rules:
    - name: require-locked-down-security-context
      match:
        any:
          - resources:
              kinds: ["Pod"]
              selector:
                matchLabels:
                  athena.dev/agent-role: lore-audit
      validate:
        message: "lore-audit pods must run with strict security context."
        pattern:
          spec:
            containers:
              - securityContext:
                  runAsNonRoot: true
                  readOnlyRootFilesystem: true
                  allowPrivilegeEscalation: false
```

## Mutate Policy Example (Role: build-agent)

```yaml
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: athena-build-agent-mutate
spec:
  background: false
  rules:
    - name: add-build-agent-env-and-labels
      match:
        any:
          - resources:
              kinds: ["Pod"]
              selector:
                matchLabels:
                  athena.dev/agent-role: build-agent
      mutate:
        patchStrategicMerge:
          metadata:
            labels:
              athena.dev/managed-by: kyverno
          spec:
            containers:
              - (name): "*"
                env:
                  - name: ATHENA_ROLE
                    value: build-agent
                  - name: ATHENA_RUN_ID
                    valueFrom:
                      fieldRef:
                        fieldPath: metadata.labels['athena.dev/run-id']
```

## Generate Policy Example (Session-Scoped NetworkPolicy)

```yaml
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: athena-generate-networkpolicy
spec:
  background: false
  rules:
    - name: generate-lore-audit-netpol
      match:
        any:
          - resources:
              kinds: ["Pod"]
              selector:
                matchLabels:
                  athena.dev/agent-role: lore-audit
      generate:
        synchronize: true
        apiVersion: networking.k8s.io/v1
        kind: NetworkPolicy
        name: "athena-deny-egress-{{request.object.metadata.labels.\"athena.dev/run-id\"}}"
        namespace: "{{request.object.metadata.namespace}}"
        data:
          spec:
            podSelector:
              matchLabels:
                athena.dev/run-id: "{{request.object.metadata.labels.\"athena.dev/run-id\"}}"
            policyTypes: ["Egress"]
            egress: []
```

## Lifecycle and Cleanup Model

1. Team Orchestrator creates workload with deterministic run/session labels.
2. Kyverno mutate/validate execute at admission.
3. Kyverno generate creates session-scoped resources.
4. On run completion/cancellation, Team Orchestrator deletes workload resources; synchronized generated resources reconcile accordingly.
5. Periodic cleanup checks for orphaned run-id resources older than TTL.

## Auditability Mapping to Team Orchestrator

Capture rejection and policy actions into Team Orchestrator events:
- `type`: `policy.rejected` | `policy.mutated` | `policy.generated`
- payload:
  - `runId`, `sessionId`, `agentRole`
  - `policyName`, `ruleName`
  - `failureAction`/`outcome`
  - `k8sResourceRef` (kind/namespace/name)

## Open Risks

1. Over-mutation drift:
- Keep mutation narrowly scoped to Athena-labeled pods only.

2. Generate fan-out:
- Bound generate rules per role and enforce naming conventions by runId.

3. Secret handling:
- Prefer referencing existing short-lived secret objects; avoid injecting secret material via policy literals.
