# Story: [Backend] Add Runtime Isolation Profile Config

**As a platform maintainer, I need config-level runtime isolation profiles so policies can select standard vs high-security execution behavior predictably.**

## Status
* Ready

## Scope
* Add config schema for isolation profiles and runtime class selection.
* Preserve backward-compatible defaults when fields are unset.
* Add config validation and normalization behavior.
* Do not wire telemetry or benchmark fixtures in this story.

## File Touchpoints
* `src/shared/config.ts`
* `src/shared/contracts.ts` (if profile contract is surfaced)
* `docs/UserGuide/02-Installation-and-Configuration.md`

## Acceptance Criteria
* Config supports profile definitions (`standard`, `high-security`) and runtime class hints.
* Existing deployments without new config remain behavior-compatible.
* Invalid config values fail fast with structured config errors.
* Operator docs include new config keys and defaults.
