# Story: Migrate Orchestrator to Directive-Harness Pattern

**As a Developer, I want the Run Orchestrator to use Directives and Harnesses so that the execution model is structured and auditable.**

## Problem Statement
The current `RunService` takes a flat `RunRequest`. We need to transition it to a model where it resolves a `Directive` and a `HarnessProfile` to execute a turn.

## Acceptance Criteria
- `RunService.run()` updated to accept `directiveId` and `harnessProfileId`.
- The resulting `RunResult` artifact links back to both IDs.
- Backward compatibility: If a raw `input` is provided, a "Shadow Directive" is created automatically.
- Audit artifacts include the full snapshot of the `HarnessProfile` used at the time of execution.

## Technical Constraints
- Ensure the state migration doesn't break existing `athena run` commands.
- Update the `EventService` to include directive/harness context in all lifecycle events.
