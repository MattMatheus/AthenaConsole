# Story: Implement Fail-Closed RBAC Rollout

**As a Platform Operator, I want to transition RBAC from observation mode to full enforcement so that I can secure the control plane without breaking existing missions.**

## Problem Statement
The current RBAC implementation defaults to `enabled: false`. When enabled, it is either `on` or `off`. We need a safe rollout path (Observe -> Soft-Enforce -> Enforce) to identify missing permissions before blocking production traffic.

## Acceptance Criteria
- Implement `authz.mode` config flag in `AthenaConfig`:
    - `off`: No authorization checks (default).
    - `observe`: Evaluate permissions, emit `authz.denied` events, but do not block.
    - `soft-enforce`: Deny only on destructive mutations (`policies:admin`, `runs:cancel`), allow-read elsewhere.
    - `enforce`: Full `fail-closed` enforcement for all service methods.
- Implement `authz.defaultDecision` config flag (valid in `observe` and `soft-enforce`).
- Update `ServiceAuthorizer` to branch its `assertAllowed` behavior based on `authz.mode`.
- Update `src/api/server.ts` to log an `AUTHZ_MODE_ACTIVE` startup event with the current enforcement level.

## Technical Constraints
- Transition from `observe` to `enforce` should not require code changes, only environment variable updates.
- Ensure that `observe` mode doesn't swallow errors from the base service if the check passes but the operation fails.
