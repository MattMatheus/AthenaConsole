# Story: [Backend] Emit Runtime Isolation Telemetry and Selection

**As an operator, I need runtime-class selection and isolation telemetry on each run so we can evaluate reliability and latency by isolation profile.**

## Status
* Ready

## Scope
* Wire runtime class/profile selection into control-plane run orchestration.
* Emit telemetry/event fields for runtime class, start mode, and latency dimensions.
* Preserve fail-closed behavior for sandbox-required high-security contexts.
* Keep API envelope semantics unchanged.

## File Touchpoints
* `src/control-plane/services.ts`
* `src/control-plane/backends.ts`
* `src/shared/contracts.ts`
* `src/control-plane/api-contracts.ts` (re-export/metadata only)
* `src/control-plane/api-schemas.ts`
* `src/control-plane/generated-component-schemas.ts` (generated)

## Acceptance Criteria
* Run orchestration applies configured isolation profile/runtime class selection.
* Telemetry contains runtime selection fields on relevant run events.
* High-security profile enforces fail-closed semantics when runtime requirements are unmet.
* Schema and contract compatibility are maintained.
* Existing non-isolated runs remain behavior-compatible when profile/runtime config is absent.

## Acceptance Tests
* Unit: runtime selection behavior by profile (default/high-security).
* Unit: telemetry payload tests for runtime-related fields.
* Contract/schema:
  * `npm run generate:schemas`
  * `npm run check:schemas`
* Regression:
  * `npm run typecheck`
