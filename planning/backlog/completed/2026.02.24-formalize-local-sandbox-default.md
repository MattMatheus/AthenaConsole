# M3.01: Formalize Podman as the Local Default

**As a New Developer, I want the system to default to a local Podman/Docker sandbox so that my first `athena run` is isolated on my machine without any cloud configuration.**

### Problem Statement
To accelerate the "inner loop" of development, the default, out-of-the-box experience should be fully local. Currently, a developer would need to understand our provider architecture to switch from a potentially cloud-focused default to a local sandbox. We must invert this.

### User Persona
- **New Contributor:** Wants to clone the repo and immediately start running agents on their local code.

### Acceptance Criteria
- [ ] The `.env.example` file is updated to set `ATHENA_EXECUTION_PROVIDER_DEFAULT` to `docker`.
- [ ] The `.env.example` file is updated to set `ATHENA_LOCK_PROVIDER_DEFAULT` to `local`.
- [ ] The core configuration in `src/shared/config.ts` is verified to prioritize these local-first defaults when no environment variables are set.
- [ ] Documentation is updated to reflect that `docker` and `local` are the defaults for execution and locking, respectively.

### Risks & Assumptions
- **Assumption:** The developer has Podman or Docker installed and its API socket is accessible. This will be a stated prerequisite in the new quickstart guide.
