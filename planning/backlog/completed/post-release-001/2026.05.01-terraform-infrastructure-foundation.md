# M5.01: Provision Core Azure Infrastructure with Terraform

**As a Platform Engineer, I want to provision the core Azure stack using Terraform, so that we have a version-controlled, repeatable environment for the Project Athena platform.**

### Problem Statement
Currently, Project Athena runs locally or in ad-hoc environments. To leverage Azure Startup Credits and move toward production readiness, we need to formalize our infrastructure using Infrastructure-as-Code (IaC).

### User Persona
- **Alex (Platform Engineer):** Needs to ensure infrastructure is predictable, documented, and easy to tear down/rebuild.

### Acceptance Criteria
- [ ] Terraform modules created for:
    - **AKS:** A cluster using `Standard_B2s` burstable nodes in the `East US` region.
    - **ACR:** A Basic tier registry for container images.
    - **Redis:** An Azure Cache for Redis (Basic C0) for distributed locking.
    - **SWA:** An Azure Static Web App for the React console.
- [ ] Environment configuration established in `infrastructure/terraform/environments/dev`.
- [ ] Infrastructure includes necessary networking (VNet, Subnets) to allow AKS to communicate with Redis.
- [ ] A successful `terraform plan` can be generated against an active Azure subscription.

### Risks & Assumptions
- **Assumption:** Azure CLI is authenticated with sufficient permissions to create Resource Groups and Service Principals.
- **Risk:** Default quotas in a new Azure subscription might limit the number of vCPUs available for AKS nodes.
