# Story: Implement Scoped Access Enforcement

**As a Platform Operator, I want to restrict users to specific personas or sessions so that agents cannot access data outside their assigned mission.**

## Problem Statement
While roles (Viewer/Operator/Admin) are functional, they are currently global. An Operator can see all sessions and cancel any run. We need to enforce the `ScopeSet` constraints defined in the architecture model.

## Acceptance Criteria
- Extend `ServiceAuthorizer` to evaluate `ScopeSet` constraints:
    - `global: true` allows access to all instances of a resource.
    - `personas: string[]` restricts `directives:*` and `runs:create` to matching persona names.
    - `sessionIds: string[]` restricts `sessions:read`, `work:*`, and `runs:cancel` to matching sessions.
    - `runIds: string[]` restricts `runs:cancelByRunId` to matching runs.
- Update `createIdentityExtractionMiddleware` to parse scope headers:
    - `x-athena-scope-personas`
    - `x-athena-scope-sessions`
    - `x-athena-scope-runs`
- On access denial due to scope mismatch, emit `authz.denied` with a `SCOPED_ACCESS_VIOLATION` detail.

## Technical Constraints
- Scope checks must be performed *after* the permission check.
- Admin role should default to `global: true`.
- Local mode (trusted header) remains the primary identity source.
