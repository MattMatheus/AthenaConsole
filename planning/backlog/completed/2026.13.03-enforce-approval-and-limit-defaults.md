## User Story

As a Team Orchestrator operator, I need task runs to enforce accepted approval and limit defaults so local, container, and HTTP/API agents fail closed when they exceed the safety envelope.

## Scope

Add the first task-run safety enforcement pass for manifest-defined limits and approval-sensitive capabilities.

## Acceptance Criteria

- Reads manifest `limits` and applies deterministic defaults when optional limit fields are omitted.
- Enforces maximum runtime duration for local-process, container-command, and HTTP/API task runs.
- Enforces observable output/artifact limits where the current run model exposes enough information.
- Records `run.stopped-by-limit` or equivalent safety-stop events with limit type, threshold, and reason.
- Updates run/task status and `safetyStop` details deterministically when a limit stops a run.
- Creates per-run approval records or events for actions/capabilities marked approval-sensitive by the manifest contract.
- Keeps existing local-process, container-command, and HTTP/API happy paths working.
- Includes focused core tests for runtime timeout, output/artifact limit handling, approval record/event creation, and unaffected successful runs.

## Non-Goals

- No global policy admin UI.
- No credential vault or external approval workflow integration.
- No kernel/container resource cgroup enforcement beyond what the current runtime abstraction can observe.
- No hosted scheduler or multi-tenant policy service.

## Engineering Handoff

- Added task-run safety resolution in `LocalTaskWorkbenchService` with deterministic defaults from ADR 0013:
  - `maxRuntimeSeconds: 900`
  - `maxToolCalls: 80`
  - `maxRepeatedActions: 3`
  - `maxRetries: 2`
  - `maxFollowUpTasks: 5`
- Emits `run.safety.limits` for every task run so the resolved safety envelope is visible in the run event stream.
- Enforces `maxRuntimeSeconds` for local-process, container-command, and HTTP/API task runs.
- Stops limit-exceeded runs with run status `stopped-by-limit`, task status `failed`, `failure` details, `safetyStop` details, and a `run.stopped-by-limit` event.
- Enforces observable envelope limits for `maxOutputBytes` and `maxArtifacts` before final output/artifact persistence.
- Records one `run.approval.required` event per manifest `permissions.approvalRequiredFor` risk class. These are event-backed approval records for this first slice and do not block otherwise valid runs.
- Preserved existing successful local-process, container-command, and HTTP/API run paths.
