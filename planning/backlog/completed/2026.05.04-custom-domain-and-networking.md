# M5.04: Configure Custom Domain and Networking

**As a Platform Operator, I want the platform to be accessible via a custom domain with SSL, so that users can securely interact with the Athena Console and API.**

### Problem Statement
Default Azure URLs (e.g., `*.azurestaticapps.net`) are not professional and don't align with our branding. We need a stable, secure endpoint for the platform.

### User Persona
- **Alex (Platform Engineer):** Needs to ensure secure ingress and correct CORS configuration for cross-origin requests between the UI and API.

### Acceptance Criteria
- [ ] Custom domain `athena.teamorchestrator.com` is configured for the Azure Static Web App.
- [ ] Managed SSL certificate is issued and bound to the custom domain.
- [ ] AKS Ingress Controller (e.g., NGINX or AGIC) is configured to expose the Control Plane API.
- [ ] `ATHENA_ALLOWED_ORIGINS` in the production environment is updated to include the custom domain.

### Risks & Assumptions
- **Assumption:** We have control over the DNS zone for `teamorchestrator.com`.
- **Risk:** DNS propagation delays can cause temporary downtime or SSL validation failures during setup.
