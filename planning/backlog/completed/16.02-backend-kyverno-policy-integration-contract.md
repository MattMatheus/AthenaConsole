# Story: [Backend] Define Kyverno Policy Integration Contract for Agent Roles

**As a platform operator, I need deterministic policy metadata and rejection surfacing so Kyverno can enforce role-based guardrails and Athena can present clear operational outcomes.**

## Status
* Ready

## Scope
* Define Athena workload metadata contract (labels/annotations) required by Kyverno policies.
* Add policy rejection/mutation/generation event shapes in control-plane telemetry surfaces.
* Ensure run rejections and policy outcomes are queryable through existing event/rejection APIs.
* Do not deploy Kyverno or implement cluster controllers in this story.

## File Touchpoints
* `src/shared/contracts.ts`
* `src/control-plane/interfaces.ts`
* `src/control-plane/services.ts`
* `src/control-plane/api-contracts.ts` (re-export + route metadata updates)
* `src/control-plane/api-schemas.ts`
* `src/control-plane/generated-component-schemas.ts` (generated)
* `docs/UserGuide/04-The-Athena-API-Server.md`

## Acceptance Criteria
* Athena defines stable metadata keys for `agent-role`, `run-id`, and `session-id` targeting.
* Policy outcomes are represented as structured events (`policy.rejected`, `policy.mutated`, `policy.generated`) with run correlation.
* Rejection history remains backward-compatible while including policy-origin details when present.
* Envelope and schema compatibility is preserved for existing API consumers.
* The story delivers contract-only integration points; no in-cluster Kyverno deployment or controller behavior is required.
