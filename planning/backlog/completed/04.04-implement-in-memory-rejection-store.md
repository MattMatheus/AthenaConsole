# Story: Implement In-Memory Rejection Store

**As a developer, I want to implement a simple, bounded, in-memory store for `RunRejectionEvent`s as a first-pass implementation, so that we can deliver observability features quickly while a more permanent solution is considered.**

## Acceptance Criteria
*   A `RejectionEventStore` service is created that can store and retrieve `RunRejectionEvent`s.
*   The store is in-memory and has a configurable, fixed size (e.g., it only keeps the latest 1000 events).
*   The store provides methods to add a new event and query for events with basic pagination.
*   The service is registered and available for dependency injection.
