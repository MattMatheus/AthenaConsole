## User Story

As a Team Orchestrator operator, I need to inspect a local task run so I can understand the timeline, logs, final output, and produced artifacts after execution.

## Scope

Build the first console run inspection path for task workbench runs, adding minimal read APIs if the console does not yet have access to run events or artifact metadata.

## Acceptance Criteria

- Operator can open a run inspection view for a task run.
- View shows run identity, task identity, assigned agent, backend, status, start/end timestamps, and failure state when present.
- View shows timeline events in chronological order.
- View distinguishes log events from lifecycle and artifact events.
- View shows final output in a readable JSON/text form.
- View shows artifact metadata with labels, formats, storage URIs, and size/hash details when present.
- View has clear rendering for completed, failed, cancelled, stopped-by-limit, and waiting-for-approval states.
- Includes focused core/console tests for read APIs, event/output/artifact formatting, and status rendering.

## Non-Goals

- No mission DAG visualization.
- No live streaming event transport.
- No artifact file preview beyond metadata unless an existing endpoint already exposes content.
- No scheduling UI.
- No remote hosted execution.

## Engineering Handoff

Completed.

Implemented the first task run inspection path.

Delivered surfaces:

- Added `GET /api/v1/task-runs/:runId` for task run detail.
- Extended task workbench contracts with run detail, event, and artifact metadata DTOs.
- Wired task run detail through `LocalTaskWorkbenchService`, API route registration, API contracts, and API schemas.
- Added console task run detail route at `/tasks/runs/:runId`.
- Added `TaskRunDetailPage` with summary metadata, terminal state detail, timeline events, final output, and artifact metadata.
- Added task run inspection model helpers for event classification, status rendering, JSON/text formatting, and artifact size formatting.

Behavior notes:

- The read API returns the task run, related task when available, chronological events, and artifact metadata.
- Timeline rendering distinguishes lifecycle, log, artifact, and error events with separate visual treatments.
- Final output, failure, and safety-stop values render as readable JSON/text.
- Artifact metadata renders label, kind, format, storage URI, size, and hash without previewing file contents.
- Completed, failed, cancelled, stopped-by-limit, waiting-for-approval, running, validating, and queued statuses have explicit badge tones.
- Browser verification used seeded local app state at `/tasks/runs/run-browser-1`.
