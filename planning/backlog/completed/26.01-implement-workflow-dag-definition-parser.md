# Story: Implement Workflow DAG Definition Parser

**As a Workflow Architect, I want to define multi-step agent tasks using a DAG schema so that I can automate complex sequences.**

## Problem Statement
Single-turn runs are insufficient for complex engineering tasks. We need a way to define a "pipeline" of agent steps where the output of one step feeds the input of another.

## Acceptance Criteria
- `WorkflowDefinition` schema supporting:
    - `steps`: Array of task nodes.
    - `dependencies`: Edges defining execution order.
    - `inputs/outputs`: Data mapping between steps.
- Parser validates the graph for Directed Acyclic Graph (DAG) properties (no cycles).
- Supports "parallel" execution for steps with no mutual dependencies.
- API endpoints `GET /api/v1/workflows` and `POST /api/v1/workflows`.

## Technical Constraints
- Use a standard format like YAML or JSON for definitions.
- Validation should be performant enough to run on every workflow submission.
