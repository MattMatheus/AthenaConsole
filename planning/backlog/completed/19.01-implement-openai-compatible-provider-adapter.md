# Story: Implement OpenAI-Compatible Provider Adapter

**As a Developer, I want to use OpenAI-compatible models so that I can run real agent turns using industry-standard LLMs.**

## Problem Statement
The current `HttpProvider` uses a proprietary schema. To use OpenAI, Groq, or Ollama, developers have to write custom middleware. We need a native adapter for the standard Chat Completions API.

## Acceptance Criteria
- A new `OpenAIProviderAdapter` is implemented.
- Supports the `https://api.openai.com/v1/chat/completions` endpoint format.
- `baseURL` is configurable via `ATHENA_OPENAI_BASE_URL` (to support Ollama/Groq).
- `apiKey` is read from `ATHENA_OPENAI_API_KEY`.
- Maps the following from the OpenAI response to Athena's `RunResult`:
    - `choices[0].message.content` -> `output`
    - `model` -> `model`
    - `usage.prompt_tokens` -> `usage.inputTokens`
    - `usage.completion_tokens` -> `usage.outputTokens`
- Handles standard HTTP errors (401, 429, 500) with appropriate retry logic.

## Technical Constraints (For Developer)
- Use the native `fetch` API.
- Register the adapter in `src/providers/index.ts`.
- Ensure it respects the `AbortSignal` for cancellations.
