# Story: [Backend] Add Sandbox Interface and Adapter Scaffold

**As a backend developer, I need a stable sandbox execution interface and local adapter scaffold so later sandbox orchestration can be added without contract churn.**

## Status
* Ready

## Scope
* Add `SandboxExecutionBackend` interface and core request/response shapes.
* Add backend factory wiring that can expose sandbox capability as disabled by default.
* Add a no-op/local placeholder adapter that returns structured "unsupported" responses.
* No run-path routing changes in this story.

## File Touchpoints
* `src/control-plane/interfaces.ts`
* `src/control-plane/backends.ts`
* `src/control-plane/services.ts` (capability exposure only)
* `src/shared/contracts.ts` (if shared DTO required)

## Acceptance Criteria
* Interface exists and compiles with strict typing.
* Local/default backend can instantiate without requiring Kubernetes dependencies at runtime.
* Capability surface indicates sandbox unavailable by default.
* No behavior regressions in existing run flows.

## Acceptance Tests
* Unit: interface adapter tests for "unsupported" and shape validation.
* Unit: backend/service capability summary includes sandbox capability flag.
* Contract/schema (only if shared contracts are modified):
  * `npm run generate:schemas`
  * `npm run check:schemas`
* Regression:
  * `npm run typecheck`
  * `npm test`
