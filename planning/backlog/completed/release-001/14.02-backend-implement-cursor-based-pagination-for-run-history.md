# Story: [Backend] Implement Cursor-Based Pagination for Run History

**As a backend developer, I need to implement cursor-based pagination for the run history API, replacing the old, unstable offset-based method.**

## Status
*   **Blocked.** Depends on the API design from `14.01`.

## Acceptance Criteria
*   The run history API endpoint is updated to support `limit` and `cursor` query parameters.
*   The data access logic is changed to fetch records "after" the provided cursor, ensuring stable pagination.
*   The API response includes the `nextCursor` needed to fetch the subsequent page.
*   The old offset-based pagination is deprecated.
