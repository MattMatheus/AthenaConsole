## User Story

As a Team Orchestrator operator, I need plugin-provided workflow templates indexed so repeatable mission/task plans can be discovered before execution is automated.

## Scope

Add the first workflow template manifest/indexing path for plugin packages.

## Acceptance Criteria

- Defines or finalizes the workflow template manifest shape used by plugin packages.
- Validates workflow template manifests during local plugin indexing.
- Stores template metadata and validation/load errors in SQLite app state or the existing plugin index model.
- Exposes a core service/API surface to list indexed workflow templates.
- Includes enough template metadata for a later story to instantiate missions/tasks from a template.
- Keeps mission run execution and template instantiation out of scope.
- Includes focused core tests for valid template indexing, invalid template diagnostics, and template listing.

## Non-Goals

- No mission run execution.
- No template-to-mission instantiation.
- No full DAG scheduler.
- No console workflow template UI.
- No remote plugin registry.

## Engineering Handoff

- Added `workflow.schema.json` for plugin-provided workflow template manifests, covering id/name/version/goal/context/tasks/UI metadata and task-level dependencies, capability requirements, agent hints, and inputs.
- Extended plugin manifests and local plugin validation to accept `workflowTemplates` references and validate referenced workflow manifests, including path containment and id/version consistency.
- Added SQLite `workflow_template_index` storage with a migration, repository, app-state database wiring, and stale-template cleanup during plugin reindexing.
- Extended local plugin indexing to persist valid workflow templates and avoid indexing templates when a plugin has validation errors.
- Added `LocalWorkflowTemplateCatalogService`, shared contracts, request parsing, route registration, API contracts/schemas, and `GET /api/v1/workflow-templates`.
- Added a bundled `multi-agent-plugin` workflow template example for podcast production.
- Added focused tests for valid indexing, invalid workflow diagnostics, explicit resource indexing, service listing/filtering, API listing, route registration, app-state migrations, and manifest validation.
