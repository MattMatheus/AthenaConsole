# Story: Implement Directive Resource Model

**As a Product Manager, I want user intent to be stored as a first-class Directive so that we can audit what was requested independently of how it was executed.**

## Problem Statement
Currently, user input is ephemeral or tightly coupled to a specific run. If we want to compare how two different agents handle the same request, we have to duplicate the input manually.

## Acceptance Criteria
- `Directive` resource defined with:
    - `id`: Unique identifier.
    - `input`: The raw user prompt or goal.
    - `contextRefs`: Optional links to files, URLs, or sessions.
    - `metadata`: Arbitrary labels for categorization.
- Directives are stored in `FileStateStore` under `directives/`.
- Directives are immutable; changes result in a new ID.
- API endpoints `GET /api/v1/directives` and `POST /api/v1/directives`.

## Technical Constraints
- Must be forward-compatible with the Workflow DAG engine (where steps consume directives).
