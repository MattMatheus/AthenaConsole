# Story: Queue Latency and Throughput Monitoring

**As a Workflow Architect, I want to identify slow agents so that I can optimize the performance of my DAGs.**

## Problem Statement
In a multi-step workflow, the entire process is only as fast as its slowest agent. We need to identify which personas or nodes are causing bottlenecks.

## Acceptance Criteria
- Real-time "Throughput" charts showing:
    - `Items/Minute` processed per queue.
    - `Queue Depth` (how many items are waiting).
- "Latency Heatmap" showing the average time an item spends in each step of a DAG.
- "Stall Alert": Visual indicator when a workflow step has been pending longer than its P95 historical duration.

## Technical Constraints
- Leverage the `WorkService` and `EventService` to calculate delta times between `enqueued` and `started`.
- Metrics should be aggregated to avoid excessive dashboard re-renders.
