# Story: Implement LSP Client Integration for Orchestrator

**As a Developer, I want the orchestrator to communicate with Language Servers so that agents can understand code structure.**

## Problem Statement
Agents currently use `grep` and `cat`, which are "dumb" tools. To perform high-quality code analysis, the agent needs semantic information (Types, Definitions, References) provided by an LSP.

## Acceptance Criteria
- `LspService` implemented in the control plane.
- Supports spawning and managing the lifecycle of LSP servers (e.g., `tsserver`, `gopls`).
- Implements the JSON-RPC communication layer.
- Provides high-level methods for:
    - `getDefinition(file, line, character)`
    - `getReferences(file, line, character)`
    - `getHoverInfo(file, line, character)`

## Technical Constraints
- Must handle LSP crashes and restarts gracefully.
- Ensure that LSP processes are killed when the Team Orchestrator orchestrator stops.
