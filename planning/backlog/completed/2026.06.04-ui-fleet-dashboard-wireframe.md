# Story: UI Fleet Dashboard Wireframe

**As a Platform Admin, I want to see a high-level overview of the system so that I can quickly verify everything is running correctly.**

## Problem Statement
The Dashboard is the first page a user sees. It needs to present the most important metrics at a glance: Active Runs, Resource Usage (CPU/Memory), and Recent Rejections/Failures.

## Acceptance Criteria
- Implement `Dashboard` feature module with:
    - `MetricsGrid`: 4-6 cards displaying "Active Runs", "Active Sessions", "System CPU (avg)", "System Memory (avg)".
    - `RecentEventsTable`: List of the last 10 system events from the `EventService` (Success/Error/Warning status indicators).
    - `CostTrendChart`: Simple SVG line chart showing "Runs per Day" (last 7 days).
- Data fetching: Use TanStack Query to fetch from `/api/fleet/summary` and `/api/events`.
- Responsive Grid: Metrics and tables should stack on smaller viewports.

## Technical Constraints
- No external charting libraries (like Recharts) yet. Use a simple SVG primitive for the trend line to keep the initial build light.
- All dashboard cards must use the shared `Card` component for consistency.
- Implement basic "Loading" and "Error" states for data-fetching sections.
