# Story: Enhance Mock Provider with JSON Schema Support

**As a Persona Developer, I want the Mock provider to return valid JSON so that I can test persona orchestration without a real LLM.**

## Problem Statement
Persona runs currently fail because the `MockProvider` returns "Echo: user input", which is not valid JSON. Since personas (like `code-review`) strictly validate their output as JSON, the mock provider must be "schema-aware."

## Acceptance Criteria
- `MockProviderAdapter` is updated to check for persona-specific metadata.
- If `metadata.trigger` is `persona:run`, return a hardcoded, schema-valid JSON string for the `code-review` persona.
- The returned JSON must include:
    - `schemaVersion: 1`
    - `mergeGate: "pass"`
    - `reportMarkdown: "Mock report content..."`
    - `findings: []`
- If no persona trigger is found, it should fall back to its existing "Echo" behavior.

## Technical Constraints (For Developer)
- Do not introduce a dependency on the persona package within the provider. 
- Use simple string detection or a lightweight "mock template" map.
