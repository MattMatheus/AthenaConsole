## User Story

As a Team Orchestrator operator, I need ready manual tasks to run through the local process backend so assigned agents can produce outputs and artifacts in local app state.

## Scope

Implement the first task execution path for assigned ready tasks using local process agent manifests.

## Acceptance Criteria

- Validates task inputs against the assigned agent manifest before run.
- Starts a run record for a ready assigned task.
- Invokes the assigned local-process/local-command agent through the runtime backend boundary.
- Records run events for validation, start, logs, completion, failure, and cancellation where applicable.
- Captures final output and artifact metadata when the agent produces them.
- Updates task/run statuses deterministically.
- Supports cancellation for an active local task run.
- Includes focused core tests for input validation, run/event persistence, output/artifact capture, failure handling, and cancellation behavior.

## Non-Goals

- No console run inspection view.
- No mission DAG execution.
- No scheduling UI.
- No remote hosted execution.
- No container or HTTP agent execution unless already exposed through the local runtime boundary.

## Engineering Handoff

Completed.

Implemented the first local-process task execution path for ready assigned tasks.

Delivered surfaces:

- Extended task workbench contracts with task run, run request, cancellation request, and cancellation result types.
- Added task run and cancellation service methods to `LocalTaskWorkbenchService`.
- Added API routes for `POST /api/v1/tasks/:id/run` and `POST /api/v1/task-runs/:runId/cancel`.
- Added API contract/schema entries for the new task run operations.
- Added focused service and API tests for local-command execution.

Behavior notes:

- `runTask` requires a ready task with an assigned loaded agent and compatible capabilities.
- Assigned agent manifests are validated for required task inputs before any run record is started.
- Local-command agents are spawned with a JSON task/agent/run envelope on stdin.
- Run records, run events, stdout/stderr log events, output, artifact metadata, and task status transitions are persisted in app state.
- Completed runs set the task to `completed`; non-zero exits and process/output/artifact failures set the task and run to `failed`.
- Active local task runs can be cancelled with best-effort `SIGTERM`, producing cancellation request and cancellation events.
- Runtime working directories are constrained to the plugin directory before process launch.
