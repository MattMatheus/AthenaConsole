# Story: Implement Fleet Metrics Aggregation API

**As an Operator, I want a single API for fleet metrics so that I can monitor the health of my entire agent cluster.**

## Problem Statement
The current metrics are node-local. For a distributed fleet, we need an "Aggregator" that provides a unified view of success rates, capacity, and resource usage.

## Acceptance Criteria
- `FleetService` updated to support aggregate queries across the `stateStore`.
- `GET /api/v1/fleet/metrics` implemented.
- Returns JSON payload containing:
    - `totalRuns`: Count of all historical runs.
    - `successRate`: Percentage of successful completions.
    - `activeCapacity`: Current runs vs. global `maxConcurrentRuns` limit.
    - `resourceAverages`: Average CPU/Memory across the fleet.
- Data is cached (TTL 60s) to ensure high performance.

## Technical Constraints
- Must be performant even when the event store contains millions of records.
- Use pre-aggregated counters where possible to avoid full table scans.
