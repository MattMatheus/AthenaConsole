# Story: [Backend] Wire Sandbox Capability Routing and Fail-Closed Policy

**As a platform operator, I need Athena run orchestration to route through sandbox execution when configured and fail closed for sandbox-required contexts when unavailable.**

## Status
* Ready

## Scope
* Add run orchestration branch: sandbox path vs existing execution path.
* Introduce policy/config hook indicating sandbox requirement for high-security runs.
* Implement fail-closed behavior when sandbox is required but unavailable.
* Preserve existing behavior for non-required contexts.

## File Touchpoints
* `src/control-plane/services.ts`
* `src/control-plane/backends.ts`
* `src/shared/config.ts` (if requirement flag is config-driven)
* `src/shared/contracts.ts` (if result/error metadata requires expansion)

## Acceptance Criteria
* Run orchestration supports sandbox-enabled path without handler logic changes.
* Sandbox-required contexts return structured rejection/error when backend is unavailable.
* Non-required contexts fall back to existing execution path.
* Cancellation/timeout flows preserve cleanup semantics and no stale running state.
* Fail-closed behavior is deterministic and test-assertable (no silent downgrade when sandbox is required).

## Acceptance Tests
* Unit: service orchestration for:
  * sandbox enabled success path
  * sandbox unavailable fallback path
  * sandbox required fail-closed path
* Reliability tests:
  * timeout/cancel behavior does not leak active run markers
  * sandbox-required unavailable path does not execute provider fallback
* Regression:
  * `npm run typecheck`
  * `npm test`
