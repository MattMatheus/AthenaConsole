# BUG-2026.001: API Server Invalid Run Error Message Assertion Mismatch

## Summary

`tests/api.server.test.ts` contains an assertion that expects the invalid run error message to include `runs.create.input`, but the current API behavior returns `runs.create requires either input or directiveId.`.

## Impact

- Targeted test runs that include this assertion fail even though runtime behavior is valid.
- Creates noise in validation during feature work.

## Location

- `/Users/foundry/Source/projectathena/tests/api.server.test.ts` (invalid run request assertion in `serves core v1 endpoints through control-plane services`).

## Reproduction

Run:

```bash
npm test -- tests/api.server.test.ts tests/control-plane.api-contracts.test.ts tests/control-plane.api-artifact.test.ts tests/control-plane.baseline.test.ts
```

Observed failure:

- Expected message to contain: `runs.create.input`
- Actual message: `runs.create requires either input or directiveId.`

## Expected Resolution

Update the assertion to match the current contract/error wording, or switch assertion to a stable invariant (error code + semantic phrase) to avoid brittle string coupling.
