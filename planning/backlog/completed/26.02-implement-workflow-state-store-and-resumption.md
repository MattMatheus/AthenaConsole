# Story: Implement Workflow State Store and Resumption

**As an Operator, I want workflows to persist their state so that I can resume them after a failure.**

## Problem Statement
If a multi-step workflow fails at Step 9 of 10, restarting from zero is a waste of time and tokens. We need "Checkpoints" for every step.

## Acceptance Criteria
- `WorkflowRun` state tracks:
    - Status of every individual step (`pending`, `running`, `ok`, `failed`).
    - Artifacts produced by each step.
    - Execution logs for the whole workflow.
- State is persisted to `FileStateStore` after every step transition.
- API endpoint `POST /api/v1/workflows/run/:id/resume` to restart from the first failed node.

## Technical Constraints
- Must handle "stale" steps (e.g., if a node was rebooted while a step was `running`).
- Ensure artifacts from previous steps are correctly re-mounted during resumption.
