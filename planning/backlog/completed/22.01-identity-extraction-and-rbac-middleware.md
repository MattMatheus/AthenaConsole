# Story: Identity Extraction and RBAC Middleware

**As a Security Admin, I want every request to be identified and assigned a role so that I can enforce authorization.**

## Problem Statement
The API currently lacks a concept of "who" is calling. We need a standard way to extract identity and map it to our internal `Viewer`, `Operator`, and `Admin` roles.

## Acceptance Criteria
- Middleware implemented in `src/api/middleware/auth.ts` (or similar).
- Extracts identity from `X-Athena-Identity` header (configurable).
- Maps identity to roles via a configurable map or static default.
- Sets `req.user` or equivalent context for downstream handlers.
- Rejects requests with no identity (Fail-Closed).

## Technical Constraints
- The mapping logic should be in the `control-plane` services, not the API handlers.
- Must be forward-compatible with JWT/OIDC claims in Milestone 4.
