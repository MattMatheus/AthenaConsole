# Story: Alert Audit and Export for A2A Observability

**As a Fleet Operator, I want stall alerts to be auditable and exportable so that operations reviews can track recurring workflow bottlenecks and remediation outcomes.**

## Problem Statement
Latency/stall monitoring is now visible in the console, but operators still need governance-grade history and export workflows for incident review and compliance evidence.

## Acceptance Criteria
- Add an additive API to list historical stall alerts with cursor pagination and filter support (`traceId`, `stepId`, `severity`, `createdAfter`, `createdBefore`).
- Add an additive CSV export API for stall alerts in a bounded time window suitable for audit review.
- Extend console observability view with alert-history filters and export action.
- Enforce fail-closed RBAC behavior:
  - Read/list/export: `Operator` and `Admin`.
  - Unauthorized identities receive deterministic `403` responses.
- Reuse persistent telemetry/event primitives; do not introduce breaking API/CLI changes.

## Technical Constraints
- Keep DTO/schema evolution additive and backward-compatible.
- Keep control-plane authorization wrappers and API contract registration aligned.
- Preserve immutable event semantics for audit/history views.
