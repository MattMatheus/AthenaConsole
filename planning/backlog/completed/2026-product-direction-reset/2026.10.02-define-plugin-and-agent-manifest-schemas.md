# Story: Define Plugin and Agent Manifest Schemas

## Status

## User Story

As a Team Orchestrator agent author, I need validated YAML-authored plugin and agent manifests so the console can discover agents, render inputs, enforce limits, and explain permissions.

## Scope

Create the first JSON Schemas and examples for plugin and agent manifests.

## Acceptance Criteria

- Defines a canonical schema location for reset manifests.
- Adds JSON Schema for `plugin.yaml`.
- Adds JSON Schema for `*.agent.yaml`.
- Schemas cover plugin identity, version, resource references, compatibility, docs, optional UI metadata, agent identity, namespaced capabilities, declared inputs, flexible outputs/artifact hints, implementation type, runtime/backend preferences, permissions, safety limits, and observability mode.
- Adds YAML examples for a single-agent plugin, a multi-agent plugin, and a local-command agent.
- Adds a validation helper or script that validates YAML manifests against the JSON Schemas.
- Includes tests or scripted validation for the examples.
- Documents schema versioning and ownership.

## Non-Goals

- No plugin installation UI.
- No runtime execution of manifest-defined agents.
- No remote plugin registry.

## Validation Expectations

- `npm --workspace @athena/core run typecheck`
- Focused tests or validation script for manifest examples.
