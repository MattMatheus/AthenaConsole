# Story: Build Local Plugin Loader and Indexer

## Status

Completed.

## Source Decisions

- `planning/architecture/0008-plugin-package-format.md`
- `planning/architecture/0010-sqlite-app-state-architecture.md`

## User Story

As a Team Orchestrator operator, I need local plugins to be discovered and indexed so installed agents can appear in the console and be assigned to tasks.

## Scope

Load local plugin folders in place, validate their manifests, and index plugin/agent metadata into SQLite.

## Acceptance Criteria

- Defines the first local plugin search path configuration.
- Loads plugins from local folders without copying them into an app-managed directory.
- Requires root `plugin.yaml`.
- Only loads first-class resources explicitly referenced from `plugin.yaml`.
- Validates referenced agent manifests using the accepted schemas.
- Records plugin load status, validation errors, enabled state, and resource metadata in SQLite.
- Supports system plugins using the same plugin package shape.
- Applies plugin enablement per workspace.
- Includes tests for valid plugin indexing, invalid plugin error capture, explicit-resource-only loading, and per-workspace enablement.

## Non-Goals

- No remote plugin registry.
- No plugin UI.
- No executable plugin test suites.
- No task assignment UI.

## Validation Expectations

- `npm --workspace @athena/core run typecheck`
- Focused core tests for plugin loading and indexing.

## Engineering Handoff

- Added first local plugin path configuration:
  - `ATHENA_PLUGIN_PATHS`
  - `ATHENA_SYSTEM_PLUGIN_PATHS`
  - default local search path: `.athena/plugins`
- Added app-state migration `2` for plugin source type metadata.
- Added SQLite repositories for:
  - plugin index records
  - agent index records
- Added local plugin loader/indexer:
  - discovers plugin roots from configured local/system search paths
  - supports search paths that point directly at a plugin root or at a directory of plugin roots
  - requires root `plugin.yaml`
  - validates plugin and referenced agent manifests against v1 schemas
  - indexes only agents explicitly referenced from `plugin.yaml`
  - records plugin status, validation errors, source type, enabled state, and manifest metadata in SQLite
  - preserves per-workspace plugin enablement across reindexing
  - treats system plugins as the same package shape with `sourceType: system`
- Added focused tests for:
  - valid plugin indexing
  - invalid plugin error capture
  - explicit-resource-only loading
  - per-workspace enablement
  - system plugin indexing
- Updated config tests for plugin search path parsing.
