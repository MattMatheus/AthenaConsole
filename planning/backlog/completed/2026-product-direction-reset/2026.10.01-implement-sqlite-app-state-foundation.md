# Story: Implement SQLite App-State Foundation

## Status

Completed.

## Source Decisions

- `planning/architecture/0010-sqlite-app-state-architecture.md`

## User Story

As a local Team Orchestrator operator, I need durable workspace app state so tasks, agents, plugins, runs, events, artifacts, schedules, and settings can be queried reliably from the console.

## Scope

Implement the first SQLite foundation for Team Orchestrator app state.

## Acceptance Criteria

- Adds the selected SQLite dependency from ADR 0010: `better-sqlite3`.
- Creates a database module that opens a per-workspace database at `.athena/team-orchestrator.sqlite`.
- Enables WAL mode.
- Adds a small hand-written SQL migration runner.
- Adds an initial migration with foundational tables for migration history, app settings, plugin index, agent index, tasks, missions, runs, run events, artifact metadata, approvals, and schedules.
- Uses a thin repository/data-access layer with prepared SQL for at least migration history and app settings.
- Includes tests that run against a temporary workspace.
- Does not migrate legacy `.athena` session/run files.
- Does not add a full ORM.

## Non-Goals

- No console UI changes.
- No plugin scanning yet.
- No task execution changes yet.
- No legacy filesystem-state migration.

## Validation Expectations

- `npm --workspace @athena/core run typecheck`
- Focused core tests for the database module and migration runner.
- Broader tests only if touched code requires them.

## Engineering Handoff
