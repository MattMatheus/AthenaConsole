# Story: Implement K8s Pod Execution Provider

**As a Platform Admin, I want to run agents in ephemeral K8s Pods for production-grade isolation.**

## Problem Statement
For production fleets, we need a backend that can scale and provide deep isolation. Kubernetes Pods allow us to leverage security features like RuntimeClasses (gVisor/Kata) and NetworkPolicies.

## Acceptance Criteria
- `K8sExecutionProvider` using `@kubernetes/client-node`.
- Dynamically creates a Pod for every run.
- Pod is deleted immediately after completion (using `activeDeadlineSeconds` for safety).
- Supports passing `RuntimeClassName` from the `HarnessProfile`.
- Streams logs back to the orchestrator for real-time visibility.

## Technical Constraints
- Must handle Pod scheduling delays and readiness checks gracefully.
- Requires a ServiceAccount with `pods/create`, `pods/log`, and `pods/delete` permissions.
