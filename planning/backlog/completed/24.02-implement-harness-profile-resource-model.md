# Story: Implement Harness Profile Resource Model

**As a Platform Operator, I want to define Harness Profiles so that I can standardize agent configurations across the fleet.**

## Problem Statement
Managing model selection, provider URLs, and toolsets for every run is inefficient. We need a way to define "Agent Envelopes" that can be reused.

## Acceptance Criteria
- `HarnessProfile` resource defined with:
    - `id`: Unique identifier.
    - `displayName`: Human-readable name (e.g., "High-Security Reviewer").
    - `config`: Model, Provider, and Tool definitions.
    - `policies`: Timeout, Retry, and Budget limits.
- Supports versioning (e.g., `v1`, `v2`) to allow rolling updates to agent logic.
- API endpoints `GET /api/v1/harness-profiles` and `POST /api/v1/harness-profiles`.

## Technical Constraints
- Validation logic to ensure the referenced provider/model exists in the current system config.
