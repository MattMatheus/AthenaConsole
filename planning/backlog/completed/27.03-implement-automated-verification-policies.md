# Story: Implement Automated Verification Policies

**As a Security Admin, I want to define policies that require evidence before a run is marked as 'pass'.**

## Problem Statement
For critical tasks, we shouldn't just take the agent's word. We should require a "Pass" to be backed by specific evidence (e.g., a green Vitest report).

## Acceptance Criteria
- `HarnessProfile` supports `verificationPolicies` (e.g., "Require evidence of type 'test-report'").
- The orchestrator checks these policies after the turn completes.
- If required evidence is missing or fails a basic check (e.g., empty file), the run status is set to `verification-failed`.
- Detailed error messages explaining which policy was not met.

## Technical Constraints
- Policy evaluation should be extensible (support regex on logs, JSON schema on reports).
