# Story: [API Design] Design Migration Path for Run-Control APIs

**As an API designer, I need to design a non-breaking migration path to move from session-scoped to run-scoped run-control APIs, so that existing clients are not broken.**

## Scope
*   Analyze the impact of changing run-control endpoints (like cancellation) to use `runId` instead of `sessionId`.
*   Propose a migration strategy. Options include:
    1.  Creating new v2 endpoints (e.g., `/api/v2/runs/{runId}/cancel`).
    2.  Creating new v1 endpoints (e.g., `/api/v1/runs/{runId}/cancel`) alongside the old ones.
*   The deliverable is a short design document with a recommendation that prioritizes client compatibility and API clarity.
