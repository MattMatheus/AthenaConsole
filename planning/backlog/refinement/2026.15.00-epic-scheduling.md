# Epic: Scheduling

## Status

Refinement.

## Goal

Allow repeatable local workflows to run later or recurringly after the task/run foundation is usable.

## Source Decisions

- `planning/architecture/0014-scheduling-model.md`

## Candidate Stories

### 2026.15.01 Add Task Schedule Model and API

Create one-shot and recurring schedules for tasks.

Acceptance criteria:

- Uses RRULE internally.
- Requires timezone with local default.
- Records schedule status.
- Records `scheduleId` on scheduled runs.

### 2026.15.02 Add Local Scheduler Service

Run due schedules while the app/API service is running.

Acceptance criteria:

- Skips missed runs by default and records missed-run events.
- Uses `skip-if-running` overlap policy by default.
- Pauses for risky action approval.

### 2026.15.03 Build Schedule UI

Create a console surface for schedule management.

Acceptance criteria:

- Create, pause, resume, disable, and delete schedules.
- Show next run, last run, and history.
- Show missed and skipped runs.

## Non-Goals

- No hosted scheduler.
- No catch-up policy beyond skipped missed runs.
- No mission or workflow-template schedule UI until task schedules work.
