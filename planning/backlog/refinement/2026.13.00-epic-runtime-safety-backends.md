# Epic: Runtime Backends and Safety

## Status

Refinement.

## Goal

Make task execution pluggable and bounded after the local-process task workbench exists.

## Source Decisions

- `planning/architecture/0011-runtime-backend-interface.md`
- `planning/architecture/0013-safety-approval-and-loop-limit-model.md`

## Candidate Stories

### 2026.13.01 Add Container Command Backend

Add first-class container-command task execution.

Acceptance criteria:

- Runs a manifest-defined container command.
- Enforces workspace and artifact boundaries.
- Captures events, logs, and artifact metadata.
- Supports cancellation.

### 2026.13.02 Add HTTP/API Backend Prototype

Add remote/API-backed task execution.

Acceptance criteria:

- Runs a manifest-defined HTTP/API agent.
- Records backend identity and response metadata.
- Emits standard run events.
- Handles cancellation as unsupported or delegated according to manifest.

### 2026.13.03 Enforce Approval and Limit Defaults

Implement the accepted safety defaults.

Acceptance criteria:

- Enforces runtime duration, tool calls where observable, repeated actions where observable, retries, and follow-up task count.
- Records `stopped-by-limit` events with limit type and reason.
- Creates per-run approval records for risky actions.

## Non-Goals

- No hosted scheduler.
- No plugin registry.
- No global multi-tenant policy system.
