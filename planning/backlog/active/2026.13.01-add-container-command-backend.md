## User Story

As a Team Orchestrator operator, I need assigned task agents to run through a container-command backend so higher-risk local work can execute with clearer workspace and artifact boundaries.

## Scope

Add the first container-command task execution backend while preserving the existing local-process path.

## Acceptance Criteria

- Recognizes manifest-defined container-command agent implementations.
- Starts task run records with backend identity `container-command` or equivalent canonical backend name.
- Enforces workspace and artifact path boundaries before launch.
- Invokes the container command through the runtime backend boundary.
- Records validation, start, log, artifact, completion, failure, and cancellation events consistently with local-process runs.
- Captures final output and artifact metadata when the container command produces them.
- Updates task/run statuses deterministically.
- Supports cancellation for active container task runs where the local container runtime exposes process control.
- Includes focused core tests for manifest validation, boundary enforcement, run/event persistence, output/artifact capture, failure handling, and cancellation behavior.

## Non-Goals

- No hosted remote execution.
- No HTTP/API task backend.
- No plugin registry.
- No global multi-tenant policy system.
- No console backend configuration UI.
