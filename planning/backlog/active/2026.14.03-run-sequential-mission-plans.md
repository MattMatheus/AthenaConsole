## User Story

As a Team Orchestrator operator, I need a mission to run its ordered tasks sequentially so a repeatable task plan can execute through the existing task-run backends without needing a full DAG scheduler.

## Scope

Add the first mission-run execution path that walks a mission's ordered task list and creates child task runs one at a time.

## Acceptance Criteria

- Adds a mission run API/service entry point that starts a run for an existing mission.
- Creates child task runs through the existing task workbench execution path so backend selection, safety limits, approvals, artifacts, and events remain consistent with manual task runs.
- Executes tasks in mission `taskOrder`, respecting simple `dependsOn` relationships already captured on tasks.
- Stops on the first failed, cancelled, or safety-stopped task by default and records the mission run status accordingly.
- Records mission run lineage so operators can connect the mission run to child task runs.
- Keeps standalone manual task runs first-class and unchanged.
- Includes focused core tests for successful sequential execution, stop-on-failure behavior, and mission/task run lineage.

## Non-Goals

- No full DAG scheduler.
- No parallel mission execution.
- No template-to-mission instantiation.
- No console mission-run UI.
- No natural-language task planning.
