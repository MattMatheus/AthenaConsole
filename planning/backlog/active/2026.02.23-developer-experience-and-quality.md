# M4.03: Improve Developer Experience and Quality

**As a Developer, I want a deterministic test pipeline, clear dependency contracts, and up-to-date onboarding documentation, so that I can contribute to the project with confidence and velocity.**

### Problem Statement
Current developer experience is hindered by several friction points. The test pipeline has intermittent failures, eroding trust. The contract for the critical docs-sync script is implicit, making it brittle. Onboarding documentation is out of sync with current project standards and processes.

### User Persona
- **Sam (Developer):** Wants to write code and merge features without fighting the toolchain.
- **New Hire:** Wants to get up to speed and contribute their first feature quickly.

### Acceptance Criteria
- [ ] The root cause of the intermittent `runtime.fallback` test failures is identified and fixed, ensuring `turbo run test` is deterministic.
- [ ] CI documentation is updated to warn against running parallel, non-isolated jobs against the same workspace artifacts.
- [ ] A new CI smoke test is created to validate the `docs-sync` contract by checking for the existence of its default manifest and source/destination paths.
- [ ] The `developer/00-onboarding.md` document is updated to reference the new `/planning` directory structure, the new `podman compose` commands, and the current cycle handoff workflow.

### Risks & Assumptions
- **Risk:** The root cause of the test flakiness is deep and time-consuming to fix.
- **Assumption:** The paths for the docs-sync contract are stable and unlikely to change frequently.
