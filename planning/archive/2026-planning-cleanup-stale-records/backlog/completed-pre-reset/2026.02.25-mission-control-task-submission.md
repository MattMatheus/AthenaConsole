# M4.05: Implement Mission Control UI for Task Submission

**As a User, I want to submit work tasks via the web interface, so that I can orchestrate the fleet without relying exclusively on the CLI.**

### Problem Statement
While the Athena CLI is powerful, it creates a barrier for users who prefer a graphical interface for configuring and launching tasks. We need a "Mission Control" center in the Console that allows users to pick specialists, configure their parameters, and execute directives.

### User Persona
- **Owner/Operator:** Wants a central dashboard to trigger specialists and monitor fleet activity.
- **Developer:** Wants to quickly launch a code review or refactoring task from their browser.

### Acceptance Criteria
- [x] Backend `SpecialistService` supports listing available specialists.
- [x] API routes `GET /api/v1/specialists` and `GET /api/v1/personas` are implemented.
- [x] A new **Mission Control** page is added to the Console.
- [x] Support for launching **Specialist Tasks** (with Git parameters).
- [x] Support for launching **Direct Directives** (with arbitrary input).
- [x] Navigation and Dashboard links are updated to point to Mission Control.

### Risks & Assumptions
- **Assumption:** The specialists are stored in the filesystem in a predictable manner that can be scanned by the backend.
