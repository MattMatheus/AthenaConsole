# Story: Resource Authorization Enforcement

**As an Operator, I want to ensure that only authorized users can perform sensitive actions.**

## Problem Statement
We have defined roles, but they are not yet checking permissions on specific resources (Runs, Policies, Schedules).

## Acceptance Criteria
- Authorization checks applied to:
    - `PolicyService`: `put` requires `Admin`.
    - `RunService`: `cancel` requires `Operator` or `Admin`.
    - `ScheduleService`: `upsert/remove` requires `Operator` or `Admin`.
- `Viewer` can access all `get/list` operations.
- Returns `403 Forbidden` with a clear reason when a check fails.
- All authorization failures are logged to the `EventService`.

## Technical Constraints
- Use a decorator or a consistent service-layer pattern to avoid boilerplate.
- Checks must be unit-testable without a full HTTP server.
