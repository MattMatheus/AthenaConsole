# Story: Build DLQ Management and Retry Console

**As an Operator, I want a UI to manage failed agent-to-agent messages so that I can recover stalled workflows.**

## Problem Statement
Asynchronous messages in the Dead-Letter Queue (DLQ) are currently invisible and unmanaged. Operators need a way to see why a message failed and attempt a recovery.

## Acceptance Criteria
- "DLQ Console" in the Admin Dashboard.
- Searchable list of all failed A2A messages with clear error reasons.
- "Inspect" view: See the raw message payload and the error stack trace.
- "Re-queue" action: Send the message back to the target agent for another attempt.
- "Discard" action: Permanently remove the message from the queue with an audit note.

## Technical Constraints
- Use the `A2aDlqService` for all data operations.
- Ensure retries use the original `traceId` to maintain the audit chain.
