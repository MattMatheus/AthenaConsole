# M4.01: Establish Foundational Governance and Process

**As a Team, we want to establish clear ownership and processes for our planning and documentation artifacts, so that we can reduce confusion, eliminate waste, and increase trust in our documentation.**

### Problem Statement
Our current planning and documentation are inconsistent. Ownership is unclear, content is sometimes duplicated or outdated, and the process for updating artifacts is not defined. This leads to confusion, wasted effort, and a lack of trust in our single source of truth.

### User Persona
- **All Team Members (Dev, Product, Marketing):** Anyone who creates or consumes project documentation.

### Acceptance Criteria
- [x] The root `planning/README.md` is updated to define the canonical owners for `backlog/`, `prompts/`, `developer/`, and `architecture/`.
- [x] The `planning/README.md` is updated with a clear policy on the `.marketing.md` files, confirming they are a separate, public-facing track.
- [x] A header comment is added to all planning documents clarifying their intended audience (e.g., `<!-- AUDIENCE: Internal/Technical -->`).
- [x] Obsolete/duplicate documents in `planning/archive/` are identified and removed.
- [x] An explicit protocol for cycle handoffs (e.g., backlog item state changes, artifact archival order) is documented in `planning/README.md`.

### Risks & Assumptions
- **Risk:** The new process is not followed, leading to the same problems recurring. (Mitigation: Gating releases on process compliance).
- **Assumption:** All team members will read and adhere to the new documented guidelines.
