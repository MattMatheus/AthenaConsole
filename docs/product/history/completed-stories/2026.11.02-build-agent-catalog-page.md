## User Story

As a Team Orchestrator operator, I need a console page for browsing installed local agents so I can understand which agents are available for tasks and why any plugins failed validation.

## Scope

Build the first console UI page over the agent catalog API.

## Acceptance Criteria

- Shows workspace and system plugins.
- Shows agent name, version, capabilities, implementation type, observability mode, and safety limits.
- Shows plugin enabled/status state and validation warnings or errors.
- Supports empty, loading, error, and validation-warning states.
- Supports capability filtering or search using the catalog API.
- Uses the new `/api/v1/agent-catalog/plugins` and `/api/v1/agent-catalog/agents` routes.
- Keeps UI copy and layout aligned with Team Orchestrator's manifest-backed agent model.

## Non-Goals

- No agent detail page.
- No task creation flow.
- No plugin install/registry flow.
- No runtime execution changes.

## Validation Expectations

- Inspect the console app scripts before choosing validation commands.
- Run the narrowest meaningful console UI validation.
- Run core API tests only if API contracts are changed.

## Engineering Handoff

Implemented the first console agent catalog page over the catalog API.

Delivered:

- Added an agent catalog console feature with API parsing, query hooks, and local TypeScript types.
- Added `/agents` route and primary navigation entry.
- Rendered workspace and system plugins with source, enabled/status state, agent counts, descriptions, and validation warnings.
- Rendered agents with name, version, plugin, capabilities, implementation type, observability mode, runtime/tool-call limits, availability, and source.
- Added capability filtering through the catalog API.
- Added client-side search, source filtering, and availability/warning filtering.
- Added loading, error, empty, and no-filter-results states.
- Verified the page with seeded local catalog data through the running API and Vite dev server.
- Cleaned up an existing console lint issue in `FleetApiService.test.ts` by adding explicit generic return types to mock client methods.
