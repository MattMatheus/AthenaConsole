## User Story

As a Team Orchestrator operator, I need to create one-shot and recurring schedules for ready tasks so repeatable work can be configured before a live scheduler service is added.

## Scope

Add the first local schedule model/service/API for task targets using the existing SQLite app-state schedule repository.

## Acceptance Criteria

- Exposes task schedule create/update/delete/list/get APIs and core service methods.
- Supports one-shot schedules and recurring RRULE-backed schedules.
- Requires timezone with a local default when omitted.
- Records schedule status and next-run metadata.
- Validates that scheduled targets are existing tasks.
- Keeps live due-schedule execution out of scope except for data needed by the later scheduler service.
- Includes focused core tests for create/list/update/delete, validation, and API contract/schema coverage.

## Non-Goals

- No background/local scheduler service.
- No missed-run processing.
- No schedule UI.
- No mission or workflow-template scheduling.
- No hosted scheduler.

## Engineering Handoff

- Added SQLite app-state schedule repository wiring for the existing `schedules` table.
- Extended `ScheduledTask` contracts with target-based schedule metadata while preserving legacy session-input schedule compatibility.
- Added task-target schedule create/update/get/list/delete support through `LocalScheduleService`.
- Validates target schedules are `targetType: "task"` for this slice and that the target task exists and is ready.
- Supports one-shot schedules through `runAt` and recurring schedule metadata through RRULE.
- Defaults timezone to the local resolved timezone when omitted and stores status/next-run/failure-policy metadata.
- Added `GET /api/v1/schedules/:id` and expanded `POST/PUT /api/v1/schedules` parsing for task-target schedules.
- Regenerated API component schemas and updated API operation schemas/contracts.
- Added focused service/API/parser/route/contract tests for task schedule create/list/get/update/delete and target validation.
