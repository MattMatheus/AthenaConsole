## User Story

As a Team Orchestrator operator, I need assigned task agents to run through an HTTP/API backend prototype so remote or hosted agents can fit the same task/run/event model.

## Scope

Add the first HTTP/API task execution backend prototype while preserving local-process and container-command paths.

## Acceptance Criteria

- Recognizes manifest-defined HTTP/API agent implementations.
- Starts task run records with backend identity `http-api` or equivalent canonical backend name.
- Validates manifest URL, method, headers/environment scoping, and compatible backend preferences before run.
- Sends a task/agent/run envelope to the remote endpoint.
- Records validation, start, response metadata, completion, and failure events consistently with other task backends.
- Captures final output and artifact metadata when the endpoint returns them.
- Updates task/run statuses deterministically.
- Handles cancellation as unsupported or delegated according to manifest.
- Includes focused core tests for manifest validation, request payload shape, response/output/artifact capture, failure handling, and cancellation behavior.

## Non-Goals

- No hosted scheduler.
- No OAuth or credential vault integration.
- No long-running polling protocol unless already exposed by the manifest shape.
- No remote plugin registry.
- No console backend configuration UI.

## Engineering Handoff

- Implemented HTTP/API task execution in `LocalTaskWorkbenchService` alongside the existing local-process and container-command paths.
- Recognizes `implementation.type: http` and `implementation.type: http-api`, canonicalizes run backend identity to `http-api`, and validates absolute HTTP(S) URLs before creating run records.
- Supports manifest `implementation.method` values `POST`, `PUT`, and `PATCH`, validates string-only implementation headers and runtime/implementation environment maps, and blocks transport-owned headers (`host`, `content-length`, `connection`).
- Sends a JSON task/agent/run envelope to the configured endpoint and records `run.response` metadata before deterministic completion or failure.
- Persists endpoint output and artifact metadata through the same run/artifact stores used by local and container backends.
- Records HTTP/API cancellation requests as unsupported for the prototype backend while allowing the in-flight run to complete or fail deterministically.
- Updated the v1 agent manifest schema for `http-api`, HTTP methods, string headers, and runtime backend preferences.
- Added focused task workbench tests for request payload shape, response/output/artifact capture, validation failures, non-OK endpoint failure handling, and unsupported cancellation.
