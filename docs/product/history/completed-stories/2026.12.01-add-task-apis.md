## User Story

As a Team Orchestrator operator, I need task API/service surfaces so the console can create, assign, list, and move manual tasks through draft and ready states.

## Scope

Expose the existing SQLite task repository through core services and API routes suitable for the console task workbench.

## Acceptance Criteria

- Creates draft tasks.
- Assigns compatible agents.
- Validates `ready` status requires an assigned agent.
- Lists tasks by status.
- Returns task metadata needed by the manual task create flow.
- Includes focused tests for service behavior, API response shape, assignment validation, and status filtering.

## Non-Goals

- No console task creation UI.
- No task execution flow.
- No mission DAG execution.
- No scheduling UI.
- No remote hosted execution.

## Validation Expectations

- `npm --workspace @athena/core run typecheck`
- Focused core tests for the new task API/service behavior.
- `npm --workspace @athena/core run test:unit` if shared API or control-plane surfaces are touched broadly.

## Engineering Handoff

Completed.

Implemented a task workbench core service and API surface over the existing SQLite task repository.

Delivered surfaces:

- Shared contracts in `packages/core/src/shared/contracts/task-workbench.ts`.
- Local service in `packages/core/src/control-plane/services/task-workbench.ts`.
- Request parsing in `packages/core/src/api/request-parsers/task-workbench.ts`.
- API routes:
  - `GET /api/v1/tasks/metadata`
  - `GET /api/v1/tasks`
  - `POST /api/v1/tasks`
  - `GET /api/v1/tasks/:id`
  - `PUT /api/v1/tasks/:id`
- API contract/schema registration for all new task operations.

Behavior notes:

- Draft task creation defaults status to `draft` and generates `task-<uuid>` ids when the caller omits an id.
- `ready` tasks require an effective `assignedAgentId`; service validation maps this to a `CONFIG_ERROR`/HTTP 400 instead of leaking repository errors.
- Assignment validation requires an indexed, loaded, enabled agent and checks all task capability requirements against the agent capabilities.
- List supports `status`, `missionId`, and `includeArchived` filters.
- Metadata returns statuses, default status, and the ready-assignment invariant for the manual task create flow.
