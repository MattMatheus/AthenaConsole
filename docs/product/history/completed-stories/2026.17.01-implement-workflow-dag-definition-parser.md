## User Story

As a workflow author, I need workflow-template task dependencies to be parsed and validated as a DAG so more complex workflows can be represented safely before execution support expands.

## Scope

Add a shared/internal parser for workflow template DAG definitions and wire it into workflow-template validation or instantiation where the current sequential task model is interpreted.

## Acceptance Criteria

- Parses workflow-template task definitions with explicit dependency references, preserving existing sequential templates.
- Validates unique task/step ids, no missing dependency references, no self-dependencies, and no dependency cycles.
- Produces a deterministic topological order and dependency map for downstream mission/task creation.
- Surfaces actionable validation errors through existing workflow-template validation/indexing paths.
- Preserves current workflow-template instantiation and sequential mission behavior for templates without explicit dependencies.
- Adds focused tests for valid DAGs, invalid references, cycles, duplicate ids, and legacy sequential templates.

## Non-Goals

- No parallel mission executor yet.
- No resume-from-step behavior yet.
- No workflow DAG visualization UI yet.
- No changes to schedule execution semantics.

## Engineering Handoff

Completed.

Implemented a shared workflow-template DAG parser and wired it into validation and instantiation:

- Added `parseWorkflowTemplateDag` / `validateWorkflowTemplateDag` for workflow task dependency definitions.
- Validates duplicate task ids, missing dependency references, self-dependencies, dependency array shape, and cycles.
- Produces deterministic topological `taskOrder` and `dependenciesByTaskId`, preserving manifest author order for legacy templates without explicit dependencies.
- Added semantic DAG validation to workflow manifest validation, so `validateManifestDocument`, `validateManifestFile`, `validatePluginPackage`, and plugin indexing surface actionable errors before invalid templates are indexed.
- Updated workflow-template instantiation to create mission task order and tasks using the parsed DAG order while preserving current sequential behavior when no dependencies are present.
- Added focused parser, manifest validation, plugin indexing, and instantiation coverage.
