# Story: Create Task, Mission, and Run Repositories

## Status

Completed.

## Source Decisions

- `docs/product/architecture/decisions/0009-task-mission-run-domain-model.md`
- `docs/product/architecture/decisions/0010-sqlite-app-state-architecture.md`
- `docs/product/architecture/decisions/0012-event-artifact-observability-model.md`

## User Story

As the console backend, I need repository APIs for tasks, missions, runs, events, and artifacts so the web app can build the first task workbench without relying on legacy session/fleet concepts.

## Scope

Add data-access APIs over the SQLite schema for the reset domain model.

## Acceptance Criteria

- Adds repository methods for creating, reading, updating, listing, and archiving tasks.
- Adds repository methods for creating, reading, updating, listing, and archiving missions.
- Adds repository methods for creating and reading runs.
- Adds repository methods for appending and listing run events.
- Adds repository methods for creating and listing artifact metadata.
- Enforces that `ready` tasks require `assignedAgentId`.
- Stores both `capabilityRequirements` and `assignedAgentId`.
- Stores task inputs as JSON.
- Supports `dependsOn: string[]` for mission task dependencies.
- Supports `proposed` follow-up tasks with `sourceRunId` and provenance metadata.
- Retains completed tasks and runs until explicit archive/delete.
- Includes focused tests for task status rules, run/event append behavior, and follow-up task creation.

## Non-Goals

- No runtime execution.
- No console UI.
- No API route exposure unless required by the local code structure.

## Validation Expectations

- `npm --workspace @athena/core run typecheck`
- Focused repository tests.

## Engineering Handoff

- Added app-state migration `3` for task dependency arrays:
  - `tasks.depends_on_json`
- Added typed SQLite repository APIs for:
  - tasks
  - missions
  - runs
  - run events
  - artifact metadata
- Wired the repositories into `openAppStateDatabase`.
- Task repository supports:
  - create, read, update, list, archive
  - `capabilityRequirements`
  - `assignedAgentId` and optional `assignedAgentVersion`
  - JSON `inputs`
  - `dependsOn: string[]`
  - `sourceRunId`
  - provenance metadata for proposed follow-ups
  - retention of completed tasks until explicit archive
- Mission repository supports:
  - create, read, update, list, archive
  - JSON context
  - ordered task references
- Run repository supports:
  - create, read, list, update
  - task and mission targets
  - output, failure, and safety stop JSON
- Run event repository supports append and ordered listing by run.
- Artifact metadata repository supports create and listing by run.
- Enforced the accepted rule that `ready` tasks require `assignedAgentId`.
- Added focused repository tests for:
  - ready task assignment rules
  - task input/capability storage
  - mission task order and task dependencies
  - completed task retention and explicit archive
  - proposed follow-up tasks with source run/provenance
  - run/event/artifact append and listing behavior
