## User Story

As a Team Orchestrator operator, I need to schedule workflow templates so recurring repeatable work can instantiate fresh missions without manual API calls.

## Scope

Extend scheduling beyond task targets by supporting workflow-template schedules that instantiate a template when due.

## Acceptance Criteria

- Adds backend scheduler execution for `targetType: "workflow-template"` using the workflow template instantiation service.
- Stores enough schedule configuration to pass template version/plugin disambiguation and default/supplied inputs.
- Records run/result metadata linking the schedule execution to the created mission and tasks.
- Updates schedule APIs or contracts only as needed for workflow-template target payloads.
- Updates the console schedule UI to select workflow templates, enter template inputs where available, and show created mission links.
- Preserves existing task schedule behavior and manual workflow-template instantiation.

## Non-Goals

- No DAG mission execution changes.
- No remote/plugin registry scheduling.
- No natural-language planner.
- No calendar UI beyond the existing schedule controls.

## Engineering Handoff

Implemented workflow-template schedule creation and execution across the core service, API contracts, and console:

- `LocalScheduleService` now accepts `targetType: "workflow-template"`, validates template disambiguation through `inputBindings`, and instantiates fresh missions/tasks with the existing workflow-template service when due or run manually.
- Schedule run results now include created `missionId` and `taskIds`; schedules expose `lastMissionId` from durable `failurePolicy.lastAttempt` metadata without overloading `lastRunId`, which remains run-record-linked.
- Schedule API parsing validates workflow-template schedule bindings, and API schemas allow the new run-result/link fields.
- The console schedule form now switches between task and workflow-template targets, renders template input controls/defaults, creates workflow-template schedules, and links schedule results/last mission metadata into the mission workbench.
- Existing task schedule behavior and manual workflow-template instantiation paths were preserved.
