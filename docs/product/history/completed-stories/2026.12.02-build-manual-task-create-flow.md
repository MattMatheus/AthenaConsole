## User Story

As a Team Orchestrator operator, I need a console flow for manually creating a task and assigning it to a compatible agent so I can prepare work before local execution exists.

## Scope

Build the first console task creation workflow on top of the task and agent catalog APIs.

## Acceptance Criteria

- Operator enters title, description, and task inputs.
- Operator selects a compatible agent.
- Inputs are rendered from the selected agent manifest.
- Task can be saved as draft or ready.
- Ready save is blocked or clearly validated until an agent is assigned.
- Created task metadata is visible after save without requiring task execution.
- Includes focused console tests for form behavior, compatibility filtering, API payloads, and ready-state validation.

## Non-Goals

- No task execution flow.
- No run inspection view.
- No mission DAG UI.
- No scheduling UI.
- No remote hosted execution.

## Validation Expectations

- `npm --workspace @athena/console run typecheck`
- `npm --workspace @athena/console run lint`
- Focused console tests for the new task create flow.
- Browser verification of draft save, ready validation, agent selection, and manifest-driven inputs.

## Engineering Handoff

Completed.

Implemented the first console manual task creation workflow at `/tasks`.

Delivered surfaces:

- Added `apps/console/src/pages/TaskCreatePage.tsx` and `TaskCreatePage.module.css`.
- Added `apps/console/src/features/task-workbench/` with API bindings, React Query hooks, task contracts, and a testable form model.
- Added the Tasks route and primary navigation item.

Behavior notes:

- Operators can enter title, description, capability requirements, select a compatible available agent, fill manifest-derived inputs, and save as draft or ready.
- Capability selections filter the assignment list to available agents satisfying every selected capability.
- Agent manifest inputs are normalized from catalog metadata and rendered as text, markdown, number, boolean, file-path, or JSON fields.
- Ready saves are blocked with visible validation until an agent is assigned.
- Required manifest inputs and numeric/JSON fields are validated before API submission.
- Successful saves show task id, status, assigned agent, and update time in the side panel without requiring execution.
