# Epic 2026.29: Real Work Run Loop

## Status

Complete.

## Goal

Make the core operator loop clear and safe: select a repo or work context, select an agent or workflow, provide structured inputs, run it, inspect outputs, and approve any risky next action.

## Problem

The console has tasks, workflows, runs, schedules, artifacts, and agents, but real work needs a tighter path with better inputs, clearer readiness, and guardrails for actions that can change files or call external services.

## Why Now

Once repos, providers, and example agents exist, the product needs a polished run loop so operators can actually use them without raw JSON or ambiguous next steps.

## Scope

In scope:

- Manifest-declared input schemas rendered as task/workflow forms.
- Required context indicators for repo, provider, model, and runtime.
- Readiness checks before run.
- Read-only, write-proposed, and write-approved run modes.
- Diff/artifact review before file modifications are applied.
- Clear run results with links to artifacts, logs, and follow-up actions.

Out of scope:

- Fully autonomous unattended code changes.
- Remote push automation.
- Complex multi-user approval workflows.

## Constraints

- Prefer safe defaults and explicit approval before repo mutations.
- Keep run history inspectable.
- Do not hide generated diffs or external actions inside opaque artifacts.

## Risks

- Too much flexibility in input schemas can make the UI brittle.
- Approval UX can become noisy if every action requires confirmation.
- Repo mutation safety needs careful boundaries before any write-capable agent is promoted.

## Validation Expectations

- Core tests for input schema validation and approval state.
- Console browser QA across task and workflow creation.
- End-to-end smoke using a repo-aware example agent with read-only and proposed-change modes.
