# Epic 2026.36: Memory Governance And Agent Integration

## Status

Future horizon.

## Goal

Make memory safe and useful inside agent runs by adding explicit read/write permissions, reviewable proposed memories, and run-linked provenance.

## Problem

Durable memory becomes risky if any agent can silently read or write it. Operators need to know which memories were used, why they were selected, and what an agent wants to remember for future work.

Memory should increase continuity without turning into hidden mutable prompt state.

## Scope

In scope:

- Agent manifest memory permissions.
- Runtime memory access contract.
- Memory read audit events.
- Agent-proposed memory writes.
- Operator approve/edit/reject flow for proposed memory writes.
- Promotion of run artifacts into memory.
- Task/run detail surfaces showing memory used and memory proposed.
- Safety defaults for sensitive memory and external-source memory.

Out of scope:

- Service-specific connector ingestion.
- Autonomous memory writes without operator review.
- Long-term memory ranking algorithms.
- Semantic retrieval backend implementation.

## Story Breakdown

### 2026.36.01 Manifest Memory Permissions

Purpose:

- Extend agent/plugin manifests so agents declare memory read/write/propose needs by namespace and sensitivity.

### 2026.36.02 Runtime Memory Context

Purpose:

- Provide memory search/get/write proposal APIs to agent runtimes through the same inspected execution envelope used for tools and artifacts.

### 2026.36.03 Memory Usage Events

Purpose:

- Emit run events when memory is searched, selected, injected, proposed, approved, rejected, or written.

### 2026.36.04 Proposed Memory Review

Purpose:

- Add console review for proposed memory writes with approve, edit, reject, and archive actions.

### 2026.36.05 Artifact Promotion

Purpose:

- Let operators promote useful run outputs and artifacts into durable memory with provenance.

### 2026.36.06 Memory-Aware Run Detail

Purpose:

- Show which memory records influenced a run and which new memories resulted from it.

## Success Metrics

- Agents cannot read or write memory unless their manifest declares the needed capability.
- Operators can approve or edit durable memory before it becomes part of future context.
- Every memory write can be traced back to a run, artifact, connector ingestion event, or direct operator action.
- Run inspection makes memory influence visible rather than mysterious.

## Risks

- Review flows can create too much friction if every small note needs approval.
- Memory injection can accidentally overfit agent behavior to stale context.
- Sensitive memory classification needs a conservative default.

## Validation Expectations

- Manifest schema tests.
- Runtime tests for denied and allowed memory access.
- API tests for proposed memory state transitions.
- Console tests for approval/edit/reject flows.
- Manual run smoke with a memory-aware sample agent.
