# Epic 2026.35: Remote Memory MVP

## Status

Future horizon.

## Goal

Deliver the first remote-capable Team Orchestrator memory service so durable memory can travel across laptop, local server, and remote server environments.

## Problem

Operators should not need to copy SQLite files to keep agent context. Memory needs a canonical source of truth reachable from every approved Team Orchestrator runtime environment.

The first implementation should be small, inspectable, and reliable before semantic retrieval or connector ingestion expands the surface.

## Scope

In scope:

- Remote memory provider implementation.
- Memory server or service endpoint for durable writes and reads.
- Token or workspace-bound authentication.
- Memory list, get, search, write, archive/delete.
- Basic snapshots.
- Provenance on every write.
- Console memory inspection surface.
- Import path from existing local markdown memory where practical.
- Product docs for configuring local and remote memory providers.

Out of scope:

- Full semantic vector retrieval.
- Rich conflict-free offline sync.
- Hosted multi-tenant administration.
- Connector-specific ingestion.
- Automatic agent memory writes without review.

## Design Principles

- Remote memory is the durable source of truth.
- Local SQLite can cache or mirror, but it is not the cross-machine product answer.
- Every write is attributable to an operator action, agent run, or system ingestion event.
- Remote memory failures should degrade clearly and visibly before agents run.

## Success Metrics

- A user can run Team Orchestrator from two machines and read the same durable memory namespace without copying local files.
- Memory writes record provenance and are visible in the console.
- Local memory cache loss does not delete durable memory.
- Product readiness distinguishes remote memory unavailable from memory disabled.

## Risks

- Service auth can become a distraction if it tries to solve full hosted identity too early.
- Poor namespace design can make later team/workspace sharing painful.
- Remote memory downtime can block runs unless degraded behavior is designed clearly.

## Validation Expectations

- Unit tests for provider behavior and namespace enforcement.
- API tests for auth, write/read/search/list/archive/delete.
- Console tests for memory inspection states.
- Manual two-environment smoke: write from one runtime, read from another.
- Product smoke updated to detect configured memory provider health.
