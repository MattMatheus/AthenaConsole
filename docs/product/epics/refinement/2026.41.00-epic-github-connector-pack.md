# Epic 2026.41: GitHub Connector Pack

## Status

Future horizon.

## Goal

Ship the first service-specific connector pack for GitHub, focused on common repository collaboration workflows.

## Problem

GitHub is the most natural first connector for Team Orchestrator because repository work is already the strongest current product use case. A GitHub pack can turn local repo analysis into practical issue, PR, and release workflows while proving the connector platform.

## Scope

In scope:

- GitHub auth binding.
- Repository, issue, pull request, commit, and release read operations.
- Issue triage agent.
- PR summarizer.
- PR review support agent.
- Release notes drafter from PRs/issues/commits.
- Repo onboarding workflow that combines local repo inspection and GitHub metadata.
- Optional approved write actions for comments, labels, or draft release notes.

Out of scope:

- Unapproved writes to GitHub.
- Full project-board automation.
- Organization-wide governance.
- GitHub Actions runner management.

## Candidate Agents

- `github.issue.triage`
- `github.pr.summarize`
- `github.pr.review-support`
- `github.release.notes-draft`
- `github.repo.onboarding`

## Candidate Workflows

- `github.pr-review-brief`
- `github.issue-triage-round`
- `github.release-prep`
- `github.repo-onboarding`

## Story Breakdown

### 2026.41.01 GitHub Read Connector

Purpose:

- Implement read-only GitHub API access through the connector platform.

### 2026.41.02 Issue And PR Agents

Purpose:

- Add issue triage, PR summary, and PR review-support agents.

### 2026.41.03 Release Notes Agent

Purpose:

- Draft release notes from selected commits, PRs, issues, and local repo context.

### 2026.41.04 GitHub Workflows

Purpose:

- Compose GitHub agents with software-team pack agents into practical review and release workflows.

### 2026.41.05 Approved Write Actions

Purpose:

- Add tightly scoped optional writes such as draft comment creation, label suggestions, or release-note drafts behind explicit approvals.

## Success Metrics

- A user can connect GitHub and run useful read-only workflows without granting write scopes.
- PR/release workflows combine remote GitHub context with local repo inspection.
- Any write requires visible approval and records an audit event.
- The pack proves connector conventions for later services.

## Risks

- GitHub rate limits and permission scopes can produce confusing failures.
- Write actions need careful UI language to avoid accidental public comments.
- Private repo data should not be stored in memory unless the operator explicitly allows it.

## Validation Expectations

- Mock GitHub fixture tests.
- Auth/scope readiness tests.
- Read-only workflow smoke with fixtures.
- Optional live smoke with a test repository.
- External write approval tests.
