# Epic: Workflow DAG Engine

## Status

Refinement.

## Goal

Move workflow templates from sequential mission creation toward durable, restart-safe, DAG-capable workflow execution.

## Source Decisions

- `docs/product/architecture/decisions/0008-plugin-package-format.md`
- `docs/product/architecture/decisions/0009-task-mission-run-domain-model.md`
- `docs/product/architecture/decisions/0011-runtime-backend-interface.md`
- `docs/product/architecture/decisions/0012-event-artifact-observability-model.md`

## Why Now

Team Orchestrator can already create tasks, group them into missions, instantiate workflow templates, run mission tasks sequentially, schedule templates, and inspect run history. The next product gap is durable multi-step workflow state: dependency readiness, restart recovery, and status surfaces that make larger workflows practical.

## Stories

### 2026.17.01 Implement Workflow DAG Definition Parser

Status: Completed.

Acceptance criteria:

- Parses explicit task dependencies.
- Validates duplicate ids, missing references, self-dependencies, and cycles.
- Produces deterministic topological order and dependency maps.
- Surfaces validation errors through manifest validation/indexing.
- Preserves sequential templates without explicit dependencies.

### 2026.17.02 Implement Workflow State Store and Resumption Logic

Status: Active.

Acceptance criteria:

- Adds durable workflow run/state records.
- Records step state, attempts, timestamps, readiness, and failures.
- Provides service helpers for create/load/update/resume.
- Recovers stale running steps after restart.
- Preserves existing mission run and workflow-template instantiation behavior.

### 2026.17.03 Add Visualizer-Friendly Workflow Status API

Status: Candidate.

Acceptance criteria:

- Exposes workflow run state, steps, dependencies, and events in a graph-friendly API.
- Supports polling by console UI without leaking internal storage shape.
- Includes failure/recovery context for each step.

## Non-Goals

- No hosted scheduler.
- No visual workflow editor yet.
- No automatic planner that invents tasks from natural language.
- No broad replacement of existing mission run behavior until workflow state proves out.
