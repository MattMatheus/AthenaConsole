# Epic 2026.26: Real Work Repo Connection

## Status

Planning intake.

## Goal

Make repository connection a first-class operator flow so Team Orchestrator can clone or select a repo and use it as run context without requiring operators to edit environment variables by hand.

## Problem

The current repo wiring guidance is honest, but it is still too manual. Operators can understand the model, but they cannot yet use the console to connect a repository, verify it, and start work against it.

## Why Now

The first-run and repo-wiring clarity work is complete. The next product step is to move from "here is how wiring works" to "connect this repo and run useful work."

## Scope

In scope:

- Console flow to add a repo by Git URL and clone it into a managed workspace location.
- Console flow to use an existing local/server path when the operator has already mounted or checked out a repo.
- Repo connection records in app-state with path, source, branch, remote, status, and last inspection metadata.
- Repo health checks for existence, Git status, current branch, last commit, and dirty state.
- Passing selected repo context into task and workflow run inputs.
- Docs for local laptop and container/server path expectations.

Out of scope:

- Hosted Git provider OAuth.
- Automatic push to remotes.
- Multi-user permissions.
- Cloud workspace synchronization.

## Constraints

- Keep local filesystem ownership explicit and reviewable.
- Never push or mutate a remote without explicit operator approval.
- Support read-only inspection before write-capable repo work.
- Keep clone destination and mounted path behavior clear for container deployment.

## Risks

- Clone and mount paths can differ between host and container.
- Operators may expect hosted Git authentication before the product supports it.
- Repo connection records can overpromise if agents do not yet consume repo context consistently.

## Validation Expectations

- Architecture review before persistence/API implementation.
- Core typecheck/tests for repository app-state and inspection service.
- Console typecheck/lint and browser QA for repo connection flows.
- End-to-end local smoke: clone/select repo, inspect status, run a repo-aware task or workflow.
