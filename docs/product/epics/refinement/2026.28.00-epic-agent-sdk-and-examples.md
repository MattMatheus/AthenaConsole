# Epic 2026.28: Agent SDK And Examples

## Status

Planning intake.

## Goal

Make it straightforward to build reusable plugin-backed agents for generic operator goals such as "summarize my articles," "find me a new chair," or "inspect this repo."

## Problem

Team Orchestrator has a manifest/plugin model, but creating a useful agent still requires too much implicit knowledge of manifests, runtime inputs, artifacts, provider access, and packaging conventions.

## Why Now

Repo and model setup will only become useful if operators and developers can quickly add agents that do real work. A small SDK and examples make the plugin model practical rather than theoretical.

## Scope

In scope:

- Agent SDK or helper package for defining agents, input schemas, provider requirements, artifacts, and execution handlers.
- Example plugin templates for common generic agents.
- At least two useful examples outside the first-run demo:
  - content/article summarizer,
  - shopping/research finder,
  - repo/codebase summarizer or test runner.
- Documentation for building, validating, loading, and testing a plugin locally.
- Test harness examples that run without external services when possible and support mocked provider calls.

Out of scope:

- Console-native agent authoring.
- Public plugin marketplace.
- Arbitrary browser automation purchasing flows.
- Hosted plugin publishing.

## Constraints

- Preserve manifest-backed agents as the source of truth.
- Keep examples safe: read-only by default, clear external-service boundaries, no hidden credential use.
- Prefer structured input schemas over raw JSON examples.

## Story Breakdown

### 2026.28.01 Agent SDK Design

Purpose:

### 2026.28.02 Agent SDK Package

Purpose:

- Add a small package that reduces boilerplate for defining plugin-backed agents and validating inputs/outputs.

### 2026.28.03 Example Agent Templates

Purpose:

- Add example plugins for generic research/content/repo tasks with clear docs and mocked tests.

### 2026.28.04 Build Your First Agent Guide

Purpose:

- Add a tutorial that takes a developer from empty plugin to loaded agent to successful run.

## Risks

- SDK abstractions can harden too early if they hide manifest concepts that are still evolving.
- Generic examples may imply web access or purchasing behavior that the runtime cannot safely support yet.
- Provider integration must be clear enough that examples do not become demos only.

## Validation Expectations

- Manifest validation for generated or example plugins.
- SDK unit tests and example plugin tests.
- Docs smoke from tutorial commands.
- Console smoke showing the example agents appear in the catalog.
