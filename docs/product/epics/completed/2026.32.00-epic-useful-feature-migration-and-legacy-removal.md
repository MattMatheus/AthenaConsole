# Epic: Useful Feature Migration And Legacy Removal

## Status

Refinement

## Problem

The Team Orchestrator pivot intentionally disconnected older Athena-era surfaces so the product could refocus on plugin-backed agents, tasks, missions, workflow runs, inspectable artifacts, readiness, and operations telemetry. Compatibility is no longer a product requirement, but several older surfaces still contain useful behavior.

The product should bring forward useful capabilities into the current model, then remove legacy compatibility paths instead of maintaining parallel systems.

## Product Principle

Useful behavior should survive. Old abstractions should not.

## Bring Forward

- Code review should become a plugin-backed sample agent, not a specialist/persona asset.
- Session/transcript/artifact inspection should become run history and run detail inspection.
- Work queue and memory APIs should become advanced runtime diagnostics only where they help operators debug real runs.
- Failed work recovery should be framed as generic failed-work recovery, not A2A-specific DLQ management.
- Deployment automation should be rebuilt only around the current local-server/LAN deployment model.
- Operations telemetry should remain, but old fleet API and contract compatibility can be removed.

## Remove

- `athena persona` and `athena specialist` commands after code-review migration.
- `/api/v1/personas*` and `/api/v1/specialists*` API routes after current paths exist.
- `packages/core/src/personas/*` and `packages/core/src/specialists/*` runtime code after no current tests depend on it.
- `specialists/athena-prime` and stale package persona docs.
- A2A-specific observability/DLQ surfaces once any useful failure-recovery behavior has a current home.
- `/api/v1/fleet/*`, `/api/fleet/*`, `FleetSummary`, and fleet-named frontend/backend compatibility aliases after operations contracts are canonical.

## Candidate Implementation Sequence

1. Migrate code-review into a plugin-backed sample agent.
2. Reframe run/session inspection into Run History and run detail artifact/transcript views.
3. Add an advanced runtime diagnostics surface for work queues and memory search if product workflows justify it.
4. Convert A2A DLQ value into generic failed-work recovery, then remove A2A-specific surfaces.
5. Remove fleet compatibility aliases and finish operations naming.
6. Remove persona/specialist runtime, CLI, API, docs, and stale checked-in assets.
7. Rebuild deployment automation only for current local-server deployment.

## Success Metric

Useful older capabilities have current Team Orchestrator homes, and old compatibility surfaces are removed rather than maintained indefinitely.
