# Epic 2026.24: Console Product Surface Polish

## Status

Complete.

## Goal

Make the console feel like a coherent Team Orchestrator product surface after the product-direction reset and first-run work, with obvious primary workflows and legacy/admin surfaces clearly contained.

## Problem

The console now supports the current runtime path, but some visible labels and pages still carry earlier product direction:

- `ProjectAthena` branding appears in the app shell and auth gate.
- The dashboard still uses fleet/governance language even though the current product center is local operator orchestration.
- Navigation mixes primary operator workflows with advanced/admin/legacy surfaces at the same level.
- `Legacy A2A DLQ`, `RBAC`, `Audit Trail`, `Resources`, `Run Templates`, `personaId`, and `harness profile` copy can make the product feel like an internal platform migration rather than an operator app.
- Placeholder pages such as Resources expose implementation plans instead of shipped operator value.

## Why Now

The first-run path is now complete enough for external review. Before adding deeper functionality, the console should stop leaking stale direction and make the main operator loop feel intentional.

## Scope

In scope:

- Console branding and route labels.
- Dashboard/home information architecture.
- Navigation grouping, ordering, and page titles.
- Copy cleanup for primary and advanced surfaces.
- Containment of legacy/admin tools without removing implemented capabilities.
- Focused browser QA across desktop and mobile widths.

Out of scope:

- Backend API renames.
- Data migrations.
- Removal of implemented admin/legacy functionality.
- Marketing site redesign.
- Broad design-system rebuild.

## Constraints

- Preserve implemented routes unless a story explicitly replaces or redirects them.
- Do not create compatibility shims for removed or renamed concepts.
- Avoid public/operator-facing references to internal delivery mechanics.
- Keep advanced tools discoverable for operators who need them, but do not let them dominate the first-run path.

## Story Breakdown

### 2026.24.01 Console Product Identity Polish

Flywheel item:

- `STORY-20260528-console-product-identity-polish`

Purpose:

- Replace visible old branding and stale product terms with current Team Orchestrator language.

Acceptance summary:

- Sidebar/auth shell use Team Orchestrator branding.
- Public console copy avoids `ProjectAthena`, legacy product-direction labels, and unexplained internal terms.
- Existing package names, API paths, storage keys, and implementation names are not renamed unless user-facing.

### 2026.24.02 Console Navigation And Surface Grouping

Flywheel item:

- `STORY-20260528-console-navigation-surface-grouping`

Purpose:

- Make primary operator workflows easy to scan while moving admin/advanced/legacy surfaces out of the main workflow path.

Acceptance summary:

- Primary navigation emphasizes dashboard, agents, workflows, missions, tasks, schedules, and sessions.
- Advanced/admin surfaces are grouped, relabeled, or visually separated.
- Placeholder routes either gain useful operator copy or are removed from top-level navigation.
- Desktop and mobile navigation remain usable without horizontal overflow.

### 2026.24.03 Operator Dashboard Polish

Flywheel item:

- `STORY-20260528-operator-dashboard-polish`

Purpose:

- Reframe the dashboard from fleet/governance telemetry into a practical operator home.

Acceptance summary:

- Dashboard copy and metrics describe local orchestration readiness, active work, recent runs/events, and next actions.
- First-run guidance remains visible but does not crowd out ongoing operator usage.
- Cost/provider-policy widgets are retained only where they match current operator needs.

### 2026.24.04 Legacy And Advanced Surface Containment

Flywheel item:

- `STORY-20260528-legacy-advanced-surface-containment`

Purpose:

- Keep implemented advanced tools available while reducing old-direction noise.

Acceptance summary:

- `Legacy A2A DLQ`, RBAC, audit, run-template, and resource/admin copy explains current value in Team Orchestrator terms.
- Empty or placeholder advanced pages no longer read like future implementation notes.
- Legacy surfaces are clearly marked as compatibility/diagnostic tools, not the recommended operator path.

## Recommended Sequence

1. Product identity polish.
2. Navigation and surface grouping.
3. Operator dashboard polish.
4. Legacy and advanced surface containment.

## Risks

- Renaming labels without changing API contracts can confuse contributors if docs do not explain the boundary.
- Hiding advanced routes too aggressively could make useful admin tools harder to find.
- Dashboard polish can expand into broad design work unless the story stays focused on visible current cruft.

## Validation Expectations

- Console typecheck.
- Focused console tests where label/model logic is introduced.
- Browser QA for affected routes at desktop and mobile widths.
- Public copy scan for stale product terms after each polish story.
- `./flywheel/tools/validate_workflow_state.sh` after backlog state changes.
