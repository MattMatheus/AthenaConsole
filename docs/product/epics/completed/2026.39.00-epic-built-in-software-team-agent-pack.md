## Goal

Ship a first-party software-team capability pack that gives new users useful agents and workflow templates immediately after setup.

## Problem

The current sample agents are helpful, but they still read as examples. New users should see a credible set of built-in agents that can inspect repositories, summarize work, review changes, explain failures, draft release notes, and guide release readiness.

This pack should be valuable without third-party service credentials, then improve when a model provider and durable memory are configured.

## Scope

In scope:

- Repo summarizer.
- Code review helper.
- Docs auditor.
- Changelog and release notes drafter.
- Test failure explainer.
- Release readiness reviewer.
- Workflow templates that compose those agents.
- Optional memory-aware behavior when durable memory is configured.
- No-auth deterministic mode where practical.
- Provider-backed mode for richer analysis.

Out of scope:

- Direct GitHub issue/PR API integration.
- External writes.
- Autonomous code modification loops.
- Connector auth primitives.

## Success Metrics

- A new operator can run a useful no-auth software workflow against a local repo.
- Provider-backed mode produces better output without changing the task/workflow structure.
- Memory-aware behavior is optional and visible.
- The pack serves as the canonical example for first-party agent quality.

## Risks

- Built-in agents can look weak if deterministic mode is too shallow.
- Provider-backed behavior can become hard to validate if prompts are not fixture-driven.
- Memory use can surprise users unless citations and run detail are clear.

## Validation Expectations

- Manifest validation.
- Fixture-based pack tests.
- Local no-auth smoke workflow.
- Provider-backed smoke where credentials are available.
- Console workflow/task run inspection smoke.
