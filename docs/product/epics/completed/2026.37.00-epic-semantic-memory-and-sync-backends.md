# Epic 2026.37: Semantic Memory And Sync Backends

## Status

Future horizon.

## Goal

Improve memory retrieval quality and backend flexibility by adding semantic search and optional provider adapters behind the Team Orchestrator memory contract.

## Problem

Keyword search is useful, but durable agent memory will eventually need semantic retrieval, hybrid ranking, and specialized backends. The product should support those capabilities without exposing raw backend concepts as the user-facing memory model.

## Scope

In scope:

- Embedding/index lifecycle for memory records.
- Hybrid keyword plus semantic retrieval.
- Provider adapter for Chroma if it remains the best near-term vector backend.
- AthenaMemory-compatible adapter exploration.
- Local cache synchronization strategy.
- Reindexing and backfill tools.
- Retrieval diagnostics in the console.

Out of scope:

- Replacing the canonical Team Orchestrator memory contract with a backend-specific API.
- Public hosted vector service operations.
- Connector-specific ingestion beyond generic memory writes.

## Story Breakdown

### 2026.37.01 Embedding Lifecycle

Purpose:

- Add embedding status, model metadata, reindex markers, and failure states for memory records.

### 2026.37.02 Hybrid Retrieval

Purpose:

- Combine keyword, semantic, metadata filter, recency, and provenance-aware ranking.

### 2026.37.03 Chroma Adapter

Purpose:

- Add Chroma as an optional backend adapter if it satisfies local/server deployment, filtering, and operational needs.

### 2026.37.04 AthenaMemory Adapter Evaluation

Purpose:

- Evaluate whether AthenaMemory should become a supported backend, import source, or conceptual reference for snapshots, episodes, and governed mutation.

### 2026.37.05 Local Cache Sync

Purpose:

- Define and implement cache refresh, invalidation, and degraded/offline behavior for remote memory.

### 2026.37.06 Retrieval Diagnostics

Purpose:

- Let operators inspect why memory results were selected, filtered, or omitted.

## Success Metrics

- Memory retrieval improves beyond exact keyword matching without changing the agent-facing API.
- Backend-specific failures are visible and recoverable.
- Local cache behavior is predictable when remote memory is unavailable.
- The product can support Chroma or AthenaMemory without making either one the product model.

## Risks

- Embedding model choice can leak data to providers if not configured carefully.
- Hybrid ranking can become hard to explain if diagnostics are weak.
- Sync behavior can become overcomplicated if offline editing is attempted too early.

## Validation Expectations

- Provider conformance tests.
- Retrieval quality fixtures.
- Reindex/backfill tests.
- Console diagnostics tests.
- Manual smoke with a semantic backend and a local cache refresh.
