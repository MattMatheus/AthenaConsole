# Epic 2026.46: Postgres Readiness - Repository Interface Freeze

## Status

Ready (readiness-gated; build only when multi-node is on the near roadmap).

## Goal

Remove direct `openAppStateDatabase` calls from services so they receive
repositories through the `AppStateDatabase` interface, enabling a future Postgres
backend behind the same interface without changing product behavior.

## Problem

`docs/product/architecture/postgres-migration-design.md` names the first
migration step as freezing domain repository interfaces and removing direct
SQLite assumptions from services. Plan 023 completed the contract-test slice:
`packages/core/tests/control-plane.app-state-contract.test.ts` now exercises the
initial backend-agnostic repository contracts against SQLite.

The remaining step-1 blocker is direct app-state opening. The direct-open
inventory has 27 grep hits: 26 service/state-store call sites and one factory
definition row included by the live grep command. Fourteen service call sites
already have an `options.appState` seam and are cheaper to convert; the biggest
clusters are `sqlite-harness-profile-state-store.ts`, `services.ts`, and the
hard helper-local opens in model providers, repositories, and operations.

This is readiness-gated work. It is large enough to plan deliberately and has low
immediate payoff until multi-node operation is near, but it is the prerequisite
for a Postgres backend that does not leak SQLite opener assumptions into
services.

## Scope

In scope:

- Convert direct service opens to injected app-state or repository providers.
- Preserve the public `AppStateDatabase` repository interface as the backend
  contract.
- Keep the plan-023 contract suite green throughout the refactor.
- Document the final interface contract and remaining backend assumptions.

Out of scope:

- Implementing the Postgres backend.
- Changing product behavior.
- Reworking offset pagination or opaque JSON-column query strategy.
- Moving local filesystem artifact paths into database payloads.
- Expanding contract coverage beyond what is needed to protect the refactor.

## Story Breakdown

### 2026.46.01 Convert Already-Seamed Service Opens

Purpose:

- Convert services that already check `options.appState` to use injected
  app-state/repository providers without local fallback opens.
- Include local-loader, local schedule service, task workbench, workflow queue
  status, workflow template catalog, mission workbench, workflow status,
  workflow DAG executor, worker heartbeats, and agent catalog.

Acceptance:

- The already-seamed cluster no longer calls `openAppStateDatabase` directly.
- Behavior is unchanged for current local construction paths.
- Validation commands pass:
  `npm --workspace @athena/core run typecheck`,
  `npm --workspace @athena/core run test:unit`, and
  `npm --workspace @athena/core run test:unit -- app-state-contract`.

### 2026.46.02 Convert The State-Store Cluster

Purpose:

- Convert `SqliteHarnessProfileStateStore` so directive, run-template, and
  harness-profile methods receive app-state/repositories instead of opening
  SQLite internally.
- Decide whether the wrapper should remain SQLite-named or be replaced by a
  backend-neutral state-store decorator.

Acceptance:

- The six state-store direct opens are removed.
- Directive, run-template, and harness-profile behavior remains unchanged.
- Validation commands pass:
  `npm --workspace @athena/core run typecheck`,
  `npm --workspace @athena/core run test:unit`, and
  `npm --workspace @athena/core run test:unit -- app-state-contract`.

### 2026.46.03 Convert High-Traffic Hard Opens

Purpose:

- Convert the remaining hard helper-local opens in model providers,
  repositories, operations, task/run service construction, local-services
  composition, and workflow service helpers.
- Preserve special semantics such as `operations.ts` returning an empty cost
  ledger summary when app-state reads fail.

Acceptance:

- High-traffic services receive app-state/repositories through constructor or
  provider injection.
- Startup recovery and durable-memory storage construction no longer require
  service-local SQLite opens.
- Validation commands pass:
  `npm --workspace @athena/core run typecheck`,
  `npm --workspace @athena/core run test:unit`, and
  `npm --workspace @athena/core run test:unit -- app-state-contract`.

### 2026.46.04 Freeze And Document The Repository Interface

Purpose:

- Treat `AppStateDatabase` as the backend contract that SQLite and future
  Postgres adapters must satisfy.
- Document lifecycle ownership, transactions or unit-of-work expectations, and
  close/disposal behavior.
- Keep the plan-023 contract suite as the regression net for any backend adapter.

Acceptance:

- Services no longer call `openAppStateDatabase` directly; the final grep returns
  only factory definitions, adapter wiring, and tests.
- The repository interface contract is documented in the migration design or a
  linked architecture note.
- Validation commands pass:
  `npm --workspace @athena/core run typecheck`,
  `npm --workspace @athena/core run test:unit`, and
  `npm --workspace @athena/core run test:unit -- app-state-contract`.

## Sequencing And Dependencies

This epic is prerequisite work for any future Postgres backend epic. Story
2026.46.01 should happen first because the already-seamed services are the
lowest-risk conversion. Story 2026.46.02 isolates the state-store cluster. Story
2026.46.03 handles the harder service and composition-root opens. Story
2026.46.04 freezes the resulting interface after the conversion pattern is
proven.

The contract tests from plan 023 must stay green throughout. Keep the
readiness-gated posture: build this when multi-node operation is near, not
speculatively.

## Acceptance Boundary

This epic is done when no service calls `openAppStateDatabase` directly, the grep
for direct opens returns only factory/adapter definitions and tests, the
plan-023 app-state contract suite still passes, and product behavior is
unchanged.
