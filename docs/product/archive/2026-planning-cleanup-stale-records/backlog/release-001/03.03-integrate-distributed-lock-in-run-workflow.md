# Story: Integrate Distributed Lock in Run Workflow

**As a developer, I need to modify the run submission workflow to use the `IDistributedLock` service, so that `maxConcurrentRuns` is enforced before a new run is initiated.**

## Acceptance Criteria
*   The run submission logic (likely in `runPersona` or a calling service) now depends on the `IDistributedLock` service.
*   Before starting a run, the code attempts to acquire a lock. The number of available locks is determined by the `maxConcurrentRuns` policy setting.
*   If a lock cannot be acquired, the API must reject the run submission with a specific, machine-readable error (e.g., `429 Too Many Requests` with a `POLICY_CONCURRENCY_LIMIT_EXCEEDED` error code).
*   The lock is reliably released when the run finishes, whether it succeeds, fails, or is cancelled.
*   Integration tests are updated to cover the new rejection scenario.
